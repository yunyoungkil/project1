# 12단계: 에셋 생성 및 준비 — Verified Asset Generator

현재 프로젝트의 05~11-2 전체 코드, DB schema, config,
CLI, 테스트 및 최신 Production Plan Report를 먼저 읽고
기존 architecture를 충분히 파악한 뒤 구현하라.

이번 단계부터 실제 외부 TTS API와 실제 파일 생성이 시작된다.

따라서 이번 단계의 목표는 단순히:

"음성 파일을 만들었다"

가 아니다.

목표는:

"13 Renderer가 신뢰하고 사용할 수 있는 검증된 실제 Asset을 확보한다."

이다.

설치 SDK에서 안정적으로 지원되지 않는다면
공식 GenerateContent TTS 경로 사용 가능.


어떤 호출 방식을 선택했는지
최종 보고서에 이유를 적는다.

==================================================
5. 공식 Gemini TTS Prompt 구조
==================================================

TTS prompt를 단순:

"Read this: ..."

만으로 만들지 않는다.


semantic prompt compiler를 구현한다.


기본 구조:

SPEECH GENERATION PREAMBLE

AUDIO PROFILE

SCENE

DIRECTOR'S NOTES

TRANSCRIPT


예:

Generate spoken audio for the transcript below.

Follow the performance directions.
Do not speak section names or production instructions.
Only speak the content under TRANSCRIPT.

### AUDIO PROFILE

Voice: Charon
Role: calm and clear educational narrator

### SCENE

A beginner English learning video for Korean adult learners.

### DIRECTOR'S NOTES

Speak naturally and clearly.
Keep the tone calm, friendly, and informative.
Do not sound theatrical.
Do not over-articulate unless the asset specifically requests
a pronunciation demonstration.

### TRANSCRIPT

...


프롬프트 preamble은 반드시:

실제 음성 생성 요청

과

실제 spoken transcript 영역

을 명확히 구분해야 한다.

7. KO_NARRATION
==================================================

Voice:

Charon


목표:

자연스럽고 명료한 한국어 교육 설명.


Prompt 방향:

- calm
- clear
- informative
- friendly
- natural Korean
- beginner-friendly
- not theatrical
- not exaggerated
- not unnaturally slow

현재 source_text를 의미적으로 수정하지 않는다.


==================================================
8. EN_NATIVE
==================================================

Voice:

Charon


목표:

영어 단어/문장 자체의 자연스러운 발음.


현재 실데이터:

BAG
BAT
MAP
CAP


Prompt 방향:

Generate only the spoken English target.

Do not spell the word.

Do not say the letter names.

Do not explain the pronunciation.

Do not add introductory words.

Speak the word once naturally.


예:

source_text:
BAG


허용:

실제 자연스러운 "bag"


금지:

"B, A, G"

"Bee ay gee"

"The word is bag"

"Bag means..."


==================================================
9. EN_NATIVE Natural vs Demonstration
==================================================

향후 다음 두 목적을 구별할 수 있다.


NATURAL

학습자가 실제 자연 발음을 듣는 목적


DELIBERATE

조금 더 명료하게 전체 단어를 확인하는 목적


단:

별도의 speech_mode를 새로 만들지 않는다.


delivery_instruction 또는 metadata로 구분.


같은 source_text라도 delivery intent가 다르면
별도 cache key가 되어야 한다.


==================================================
10. EN_PHONEME_DEMO — Critical
==================================================

현재 실데이터에는:

/b/
/æ/
/g/
/b-æ-g/

/t/
/b-æ-t/

/m/
/p/
/m-æ-p/

/k/

등이 존재할 수 있다.


이 영역은 일반 TTS보다 훨씬 위험하다.


절대:

source_text="/æ/"

를 그대로 TTS에 던진 뒤
모델이 정확한 /æ/를 낼 것이라고 가정하지 않는다.


절대:

/æ/ → "애"

같은 한국어 치환으로 성공 처리하지 않는다.


source of truth:

IPA


이어야 한다.


==================================================
11. Phoneme Generation Strategy
==================================================

EN_PHONEME_DEMO asset에는 최소:

source_text

expected_pronunciation

tts_input_text

generation_strategy

를 추적한다.


generation_strategy 예:

DIRECT_PHONEME_PROMPT

CONTEXT_EXTRACTION

UNSUPPORTED


A. DIRECT_PHONEME_PROMPT

Gemini에게 목표 음소만 발화하도록 명확하게 지시.


B. CONTEXT_EXTRACTION

단독 음소가 불안정할 경우
해당 음소를 포함하는 짧은 pronunciation demonstration을 생성하고
후처리로 목표 부분을 추출할 수 있는 infrastructure가 실제 존재할 때만 사용.


후처리 extraction infrastructure가 없다면
가짜로 구현하지 않는다.


C. UNSUPPORTED

정확성을 검증할 수 없고 생성 결과도 불안정한 경우
정직하게 FAILED / UNVERIFIED 처리.


==================================================
12. Blended IPA Asset
==================================================

현재 Production Plan에:

/b-æ-g/
/b-æ-t/
/m-æ-p/

같은 asset이 존재한다.


이것은 단일 phoneme과 다르다.


목표:

각 phoneme을 끊어서 이름처럼 읽는 것이 아니라
blending demonstration 역할.


예:

/b/ ... /æ/ ... /g/

→ 점점 연결

→ BAG


실제 Gemini TTS가 이 구조를 안정적으로 만들 수 있는지
대표 asset 1개를 먼저 실험한다.


성공을 미리 가정하지 않는다.


필요하면 12-1 TTS 발음 최적화 대상으로 남긴다.


==================================================

==================================================

현재 BAG Production Plan에서는 0개일 수 있다.

필수.

예:

==================================================
14. ORIGINAL_NATIVE_AUDIO
==================================================

TTS 호출 금지.


Source Clip Candidate의 실제 source file에서 추출.


원본 file이 없으면:

FAILED 또는 MISSING_SOURCE


인터넷에서 임의 검색하여
대체하지 않는다.


현재 EDUCATION 실데이터에서는:

ORIGINAL_NATIVE_AUDIO = 0


이어야 한다.


==================================================
15. Gemini Audio Tags
==================================================

Gemini 3.1 Flash TTS의 audio tag를 사용할 수 있다.


하지만 approved tag subset을 작게 유지한다.


초기 허용 후보:

[slow]
[short pause]
[long pause]


Podcast에서 필요 시:

[laughs]
[sighs]

등을 별도 허용할 수 있다.


중요:

audio tag는 영어로 작성.


두 tag를 바로 연속 배치하지 않는다.


모든 asset에 tag를 억지로 넣지 않는다.


EDUCATION의 기본 narration에는
natural language Director instruction을 우선하고,
tag는 정말 필요한 부분만 사용한다.


==================================================
16. PAUSE — 매우 중요
==================================================

11단계에는:

TIMELINE PAUSE

가 존재한다.


현재 CAP:

3000ms


이 3초는 Gemini TTS 내부 pause로 생성하지 않는다.


즉:

[long pause]

로 CAP 3초를 대체하면 안 된다.


현재 3초 thinking time:

Renderer timeline이 정확히 보장해야 하는
explicit production pause.


12단계는 metadata를 보존할 뿐이다.

==================================================

A.

자연스러운 호흡/표현


B.

TIMELINE_PAUSE

TIMELINE_PAUSE

Listener challenge:

TIMELINE_PAUSE

==================================================
18. Gemini Long Output Chunking
==================================================

긴 narration을 하나의 TTS 요청으로
몇 분씩 생성하지 않는다.


Google 공식 limitation을 고려해
작은 의미 단위로 생성한다.


현재 11단계에서 Speech Asset 자체가
이미 비교적 작은 segment로 나뉘어 있으므로
기본적으로 Speech Asset 단위 생성이 적절하다.


Podcast에서는 Dialogue Beat 또는
자연스러운 conversation chunk 단위로 묶을 수 있다.


문장 중간에서 임의 절단 금지.

==================================================

duration_ms

를 저장.

25. Cache
==================================================

Gemini API 자체의 model-side caching 지원 여부와 무관하게
우리 application-level asset cache를 구현한다.


cache key 최소:

model

voice

speech_mode

tts_input_text

delivery_instruction

audio tag configuration


해시 기반.


source_text만으로 cache key를 만들지 않는다.


==================================================
26. Replay Reuse
==================================================

같은 BAG 발음을 여러 곳에서 사용한다면
새 API 호출하지 않는다.


동일 asset reuse.


현재 11단계 deduplication 결과를 존중.


replay_group이 같은 경우
가능하면 동일 generated asset 참조.


==================================================
27. API Retry
==================================================

Gemini 3.1 Flash TTS는
간헐적으로 정상 audio 대신 실패하는 경우가 있을 수 있으므로
자동 retry 구현.


config:

asset_generation:
  max_retries: 3


retry 대상:

500/server error

temporary network error

empty response

missing audio output


무한 retry 금지.


==================================================
28. Prompt Rejection / Wrong Output
==================================================

모호한 prompt 때문에:

style instruction을 읽음

audio가 아닌 비정상 response

speech synthesis rejection

등이 발생하면:


첫째:

clear speech-generation preamble 확인


둘째:

TRANSCRIPT boundary 명확화


셋째:

retry


하지만 source_text의 의미를 바꾸지 않는다.


==================================================
29. EN_NATIVE Validation
==================================================

실제 EN_NATIVE BAG이:

"B A G"

처럼 spelling되면 실패.


현재 프로젝트에 reliable ASR이 없다면
자동으로 "발음 정상 PASS"라고 주장하지 않는다.


최소 상태:

FILE_VALID
+
CONTENT_UNVERIFIED


로 분리 가능.


단:

실제 샘플 검증에서는 사람이 직접 들어볼 수 있도록
생성 파일 경로를 보고서에 보여준다.


==================================================
30. Phoneme Validation
==================================================

/æ/ 대표 샘플은 특히
자동 PASS 금지.


검증 상태 taxonomy 예:

VALIDATED

UNVERIFIED

FAILED


정확한 phonetic validator가 없다면:

UNVERIFIED


로 둔다.


하지만:

file generation 자체는 성공했다면
generated status와 pronunciation validation을 분리한다.


예:

status:
AVAILABLE

pronunciation_validation:
UNVERIFIED
