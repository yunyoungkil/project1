현재 YouTube Market Research CLI의 터미널 UX를 개선해줘.

목표는 기능 변경이 아니라,
사용자가 터미널만 보고도 현재 상태를 직관적으로 알 수 있게 만드는 것이다.

중요:
- 분석 로직 변경 금지
- API 호출 방식 변경 금지
- Outlier/baseline/opportunity 계산 변경 금지
- Weekly Report 구조 변경 금지
- logging/progress UX만 개선
- 기존 CLI 명령 시그니처 유지


==================================================
1. 전체 단계 상태 표시
==================================================

run-all 실행 시 다음 단계를 명확하게 표시해라.

[START] 전체 실행 시작

[SEARCH] category 검색 시작/완료

[ANALYZE] 분석 시작/진행/완료

[PATTERNS] 제목 패턴 분석 시작/진행/완료

[CHANNEL] 내 채널 데이터 동기화 시작/완료

[TOPIC] topic score 계산 시작/완료

[REPORT] 리포트 생성 시작/완료

[DONE] 전체 파이프라인 완료


==================================================
2. 진행률 표시
==================================================

analyze와 patterns는 오래 걸릴 수 있으므로 진행 상황을 보여줘.

예:

[ANALYZE] 25/352
[ANALYZE] 50/352
[ANALYZE] 100/352

[PATTERNS] 1/50
[PATTERNS] 10/50
[PATTERNS] 20/50

너무 많은 로그를 찍지 말고
10개 단위 또는 10% 단위로 출력해라.


==================================================
3. Warning / Error 구분
==================================================

사용자가 다음 상태를 명확히 구분할 수 있게 해라.

정상 진행:
[INFO]

주의하지만 계속 진행:
[WARN]

실패하고 중단:
[ERROR]

완료:
[DONE]

예:

[WARN] Gemini JSON 파싱 실패
       → rule-based fallback으로 계속 진행

[ERROR] YouTube API 호출 실패
        stage=analyze
        channel_id=...
        reason=...


==================================================
4. Gemini fallback 표시
==================================================

Gemini 오류가 발생해도 전체 파이프라인이 계속된다면
반드시 터미널에 다음처럼 명확하게 표시해라.

[WARN] Gemini 분석 실패 (12/50)
       reason: Unterminated string ...
       fallback: rule-based
       pipeline continues

사용자가 에러인지 중단인지 헷갈리지 않게 한다.


==================================================
5. 단계별 요약
==================================================

각 단계 완료 후 짧은 요약을 출력한다.

예:

[SEARCH DONE] reading
  queries: 13
  cached: 13
  api calls: 0
  new videos: 0

[ANALYZE DONE]
  total: 352
  processed: 258
  unknown_type: 16
  no_baseline: 21
  below_threshold: 78

[PATTERNS DONE]
  total: 50
  gemini_success: 42
  fallback: 8


==================================================
6. 최종 요약
==================================================

run-all이 끝나면 반드시 마지막에 아래와 비슷한 요약을 출력한다.

========================================
YouTube Market Research 완료
========================================

Search: PASS
Analyze: PASS
Patterns: PASS
Channel Sync: PASS
Topic Score: PASS
Report: PASS

Report:
reports/weekly_YYYY-MM-DD.md

Quota used:
XXX units

Warnings:
Gemini fallback X건

Result:
SUCCESS
========================================


==================================================
7. 실패 시
==================================================

중간 단계에서 fatal error가 발생하면
최종적으로 명확하게 출력한다.

========================================
YouTube Market Research 실패
========================================

Failed stage:
PATTERNS

Reason:
...

Completed stages:
Search PASS
Analyze PASS

Report:
NOT CREATED

Result:
FAILED
========================================

traceback은 유지해도 되지만
사람이 읽기 쉬운 요약을 traceback 앞이나 뒤에 반드시 출력한다.


==================================================
8. 구현 방식
==================================================

가능하면 공통 helper를 만들어라.

예:

log_stage_start()
log_stage_done()
log_progress()
log_warning()
log_error()
print_run_summary()

ANSI 색상은 선택사항이다.

Windows PowerShell에서 깨지지 않는 것을 우선한다.

색상을 넣는다면:
- INFO 기본색
- WARN 노랑
- ERROR 빨강
- DONE 초록

색상 미지원 환경에서도 텍스트 prefix만으로 의미가 전달되어야 한다.


==================================================
9. 테스트
==================================================

다음을 테스트해라.

1. run-all 정상 실행 시 START/DONE 출력
2. analyze progress 출력
3. patterns progress 출력
4. Gemini 실패 시 WARN + fallback 표시
5. fatal error 시 ERROR + failed stage 표시
6. report 생성 완료 경로 출력
7. 기존 기능 테스트 전체 통과

완료 후 전체 pytest 실행.
