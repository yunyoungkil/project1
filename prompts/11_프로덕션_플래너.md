# 11단계: Production Planner 구현

현재 프로젝트의 05~10단계를 먼저 충분히 읽고 기존 구조/DB/테스트/CLI 패턴을 파악한 뒤 구현하라.

중요:
- 기존 기능을 삭제하거나 의미를 변경하지 않는다.
- 05~10단계 산출물은 읽기 전용이다.
- 기존 테스트를 깨뜨리지 않는다.
- 이번 단계는 "실제 렌더링" 단계가 아니다.
- 실제 영상 생성, 실제 TTS API 호출, 실제 클립 다운로드/편집을 하지 않는다.
- 11단계의 책임은 10단계 Video Direction을 "실제로 제작 가능한 Production Plan"으로 변환하는 것이다.
- 특히 음성/TTS는 실제 음성 파일을 만드는 것이 아니라 Speech Asset Spec을 생성한다.
- 향후 Asset Generator / Renderer가 이 Plan을 그대로 실행할 수 있어야 한다.


==================================================
0. 11단계의 역할
==================================================

파이프라인:

09 Content Script
    ↓
10 Video Director
    ↓
11 Production Planner   ← 이번 구현
    ↓
12 Asset Generation     ← 아직 구현하지 않음
    ↓
13 Renderer             ← 아직 구현하지 않음

11단계는 다음 질문에 답해야 한다.

"10단계에서 선택한 포맷과 Block Direction을
실제로 어떤 음성, 원본 클립, 자막, 시각 요소, pause,
replay, viewer interaction 순서로 제작해야 하는가?"

그러나 다음은 하지 않는다.

- TTS API 실제 호출
- mp3/wav 생성
- 영상 다운로드
- 영상 자르기
- FFmpeg 실행
- Remotion 렌더링
- 이미지 생성
- 자막 영상 렌더링
- 실제 duration을 TTS 결과 없이 임의 확정

즉:

Production Intent
→ Production Specification

까지만 담당한다.

3. 지원 Format
==================================================

10단계의 final_format을 그대로 존중한다.

CLIP_ANALYSIS
HYBRID
PODCAST

==================================================
4. Voice Casting — 고정 정책
==================================================

채널 기본 Narrator:

Charon

적용:

EDUCATION → Charon
CLIP_ANALYSIS 설명 → Charon
HYBRID 교육/설명 → Charon

PODCAST:

female_host → Zephyr
male_host → Charon


중요:

Voice와 Speech Mode는 별개 개념이다.

Charon이라고 해서 모든 speech segment가 같은 방식으로
생성되어서는 안 된다.


==================================================
5. Speech Mode Taxonomy
==================================================

반드시 다음 taxonomy를 사용한다.

KO_NARRATION
EN_NATIVE
KO_PRONUNCIATION_GUIDE
EN_PHONEME_DEMO
ORIGINAL_NATIVE_AUDIO

임의 taxonomy를 추가하지 않는다.

각 speech segment는 정확히 하나의 speech_mode를 가진다.


==================================================
6. Speech Mode 자동 판정 우선순위
==================================================

다음 우선순위를 결정론적 기본 정책으로 구현한다.


Priority 1:

실제 원본 발화 자체가 학습/분석 대상이며
10단계 Source Clip Candidate가 연결되어 있는가?

YES
→ ORIGINAL_NATIVE_AUDIO


Priority 2:

실제 영어 단어/구/문장의 자연스러운 정답 발음을
학습자에게 들려주는 것이 목적인가?

YES
→ EN_NATIVE


Priority 3:

개별 영어 음소 또는 음소 결합을 시연하는가?

예:

/b/
/æ/
/g/

또는

/b/ + /æ/ + /g/

YES
→ EN_PHONEME_DEMO


Priority 4:

한국인 학습자가 영어를 어떻게 들을 수 있는지를
한글 근사 발음으로 설명하는가?

예:

like a
→ "라이커처럼 들릴 수 있습니다."

YES
→ KO_PRONUNCIATION_GUIDE


그 외 한국어 설명:

→ KO_NARRATION


==================================================
7. 중요한 Speech 분리 원칙
==================================================

다음과 같은 문장을 하나의 TTS asset으로 만들지 않는다.

"이번에는 BAG를 들어보겠습니다. BAG."

반드시:

SPEECH01
KO_NARRATION
"이번에는 BAG를 들어보겠습니다."

SPEECH02
EN_NATIVE
"BAG"

로 분리한다.


또한:

"B는 /b/, A는 /æ/, G는 /g/입니다."

를 하나의 narration asset으로 보내지 않는다.

교육 구조에 맞게:

KO_NARRATION
"먼저 각각의 소리를 들어보겠습니다."

EN_PHONEME_DEMO
/b/

EN_PHONEME_DEMO
/æ/

EN_PHONEME_DEMO
/g/

처럼 분리할 수 있어야 한다.


==================================================
8. EN_NATIVE
==================================================

목적:

실제 영어 정답 발음을 들려주는 것.

예:

BAG
CAP
Sounds like a plan.
What are you doing?

기본 Voice:

Charon

단:

CLIP_ANALYSIS/HYBRID에서
사용자가 제공한 원본 영상의 실제 발화가 학습 대상이고
10단계에서 적절한 Source Clip Candidate가 확보됐다면

ORIGINAL_NATIVE_AUDIO를 우선한다.

즉:

ORIGINAL_NATIVE_AUDIO
    >
EN_NATIVE TTS

단순히 영어 텍스트가 있다는 이유로
모든 영어를 EN_NATIVE asset으로 만들지 않는다.

교육적으로 실제 발음을 들려줄 필요가 있을 때만 생성한다.


==================================================
9. ORIGINAL_NATIVE_AUDIO
==================================================

실제 원본 영상 음성이다.

TTS를 생성하지 않는다.

반드시 source_clip_candidates의 실제 후보를 참조해야 한다.

필수 정보:

source_clip_candidate_id
source_ref
focus_in
focus_out
context_in
context_out
clip_role
clip_score
clip_grade

원본 영상에 없는 발화를 임의로 ORIGINAL_NATIVE_AUDIO로
계획하면 안 된다.


==================================================
10. KO_NARRATION
==================================================

한국어 교육 설명.

Voice:

Charon

예:

"이번에는 BAG를 보겠습니다."

"이 세 소리를 이어보겠습니다."

"방금 어떻게 들리셨나요?"


한국어 문장 안에 영어 target word가 들어있다고 해서
문장 전체를 EN_NATIVE로 보내면 안 된다.

필요하면 segment를 분리한다.


==================================================
11. KO_PRONUNCIATION_GUIDE
==================================================

한국인 초보 학습자를 위한
"듣는 느낌"의 한글 근사 발음.

중요:

이것은 영어 발음의 정답이 아니다.

예:

Sounds like a plan.

한글 근사:

"사운즈 라이커 플랜"

저장 시 반드시:

speech_mode:
KO_PRONUNCIATION_GUIDE

approximation_only:
true


그리고 educational metadata에서
영어 음소와 동일한 것으로 취급하지 않는다.

금지:

/æ/ = 애

허용:

phoneme:
/æ/

korean_approximation:
"애"

approximation_only:
true


가능하면 narration도:

"라이커라고 발음합니다."

보다

"라이커처럼 들릴 수 있습니다."

같은 표현을 우선한다.


==================================================
12. EN_PHONEME_DEMO
==================================================

이 부분은 특히 중요하다.

09 Content Script에서:

B /b/ + A /æ/ + G /g/

처럼 IPA가 정확성의 source of truth로 저장되어 있다.

그러나:

IPA 문자열 자체를 그대로 Gemini TTS에 던져
정확한 음소가 생성된다고 가정하면 안 된다.


따라서 Speech Asset에는 분리 저장:

speech_mode:
EN_PHONEME_DEMO

source_text:
/æ/

expected_pronunciation:
/æ/

tts_input_text:
<12단계 TTS 생성기가 사용할 발음 최적화 입력>


11단계는 실제 음성을 생성하지 않는다.

tts_input_text는 발음 생성 의도를 보존하되
IPA source of truth를 잃지 않아야 한다.


절대:

/æ/ → "애"

로 변환해 source of truth를 덮어쓰지 않는다.


==================================================
13. Gemini 3.1 Flash TTS Preview 대응
==================================================

향후 TTS 생성 모델:

Gemini 3.1 Flash TTS Preview

Voice:

Narrator:
Charon

Podcast:
Zephyr + Charon


11단계에서는 모델을 실제 호출하지 않는다.

대신 각 Speech Asset에
TTS 생성에 필요한 semantic direction을 저장한다.

예:

voice_name
speech_mode
language_code
tts_input_text
delivery_instruction
pace_intent
emphasis_intent


중요:

실제 API parameter가 존재한다고 확인되지 않은
speed/pitch/style 같은 가짜 parameter를 만들지 않는다.

모델이 자연어 style instruction을 지원하는 경우를 대비해
semantic instruction으로 저장한다.


예:

KO_NARRATION:

"Calm, clear Korean educational narration.
Speak naturally and clearly for a beginner learner.
Do not sound theatrical."


EN_NATIVE:

"Produce one natural native-like English pronunciation.
Do not spell the word.
Do not add explanation."


EN_PHONEME_DEMO:

"Produce only the target English sound for pronunciation demonstration.
No letter name. No explanation."


KO_PRONUNCIATION_GUIDE:

"Read this Korean approximation naturally as a Korean pronunciation guide.
It is a learner aid, not the authoritative English pronunciation."


==================================================
14. TTS Prompt Injection / Text Safety
==================================================

교육 텍스트 자체와
TTS direction을 분리 저장한다.

예:

source_text:
"BAG"

delivery_instruction:
"Produce one natural English pronunciation."

두 필드를 하나의 의미 없는 문자열로 영구 저장하지 않는다.

향후 12단계가 Gemini TTS 요청을 조립한다.


==================================================
15. Pause 설계
==================================================

Pause는 Production Plan의 first-class object로 취급한다.

최소:

pause_before_ms
pause_after_ms

그리고 viewer_action이 있는 경우:

thinking_time_seconds

를 그대로 보존한다.


특히 09/10에서:

CAP
thinking_time_seconds = 3

이면 11단계에서도 정확히 3초를 보존한다.

정답 음성을 pause 전에 배치하면 안 된다.


예:

KO_NARRATION
"이번에는 여러분이 직접 읽어보세요."

EN/visual target presentation

PAUSE
3000ms

EN_NATIVE
"CAP"


==================================================
16. Pause Visualization Metadata
==================================================

아직 실제 animation을 만들지는 않는다.

하지만 향후 Renderer가 사용할 수 있도록
pause_visual_behavior를 정의한다.

허용 taxonomy:

HOLD_HIGHLIGHT
FREEZE_WAVEFORM
THINKING_DOTS
CLEAN_HOLD
NONE


예:

viewer thinking time:

THINKING_DOTS 또는 CLEAN_HOLD


일반적인 TTS 호흡 pause:

HOLD_HIGHLIGHT 또는 FREEZE_WAVEFORM


주의:

11단계는 "화면 좌측 300px" 같은
renderer-specific 좌표를 만들지 않는다.


==================================================
17. Karaoke / Speech Synchronization 준비
==================================================

Speech Asset에는 향후 word timing을 받을 수 있도록:

sync_required:
true/false

highlight_mode:

WORD
PHRASE
NONE

정도만 정의한다.


실제 word timestamps는
TTS 생성 이후에만 알 수 있으므로
11단계에서 임의 생성하지 않는다.


==================================================
18. EDUCATION 제작 문법
==================================================

EDUCATION Block은 기본적으로:

Explanation
→ Example
→ Demonstration
→ Viewer Attempt
→ Answer
→ Reinforcement

중 해당 Block의 learning_function에 필요한 것만 사용한다.

모든 Block을 같은 템플릿으로 강제하지 않는다.


visual_spec은 semantic하게 저장:

TARGET_WORD
PHONEME_SEQUENCE
KEY_CONCEPT
COMPARISON
QUESTION
ANSWER_REVEAL
RECAP

등.


Renderer-specific instruction은 금지.


==================================================
19. CLIP_ANALYSIS 제작 문법
==================================================

기본 흐름:

Context
→ Original Clip
→ Viewer Question
→ Replay
→ Explanation
→ Focus Replay
→ Learner Reconstruction
→ Final Replay


하지만 모든 Clip을 무조건 3회 반복하지 않는다.

Content Block 목적에 따라 필요한 횟수만 계획한다.


중요:

원본 Clip은 "장식"이 아니라
교육적 evidence로 사용한다.


예:

ORIGINAL_NATIVE_AUDIO

↓

KO_NARRATION
"방금 어떻게 들리셨나요?"

↓

필요한 설명

↓

ORIGINAL_NATIVE_AUDIO replay


==================================================
20. HYBRID 제작 문법
==================================================

10단계 Block Direction을 그대로 따른다.

어떤 Block은:

EDUCATION

어떤 Block은:

CLIP_ANALYSIS

가 될 수 있다.


11단계에서 전체를 억지로 한 문법으로 통일하지 않는다.

교육적으로 실제 clip이 필요한 Block에서만 clip을 사용한다.


==================================================
21. PODCAST 제작 문법
==================================================

PODCAST는 다른 3개 Format과 완전히 분리한다.

두 진행자:

female:
Zephyr

male:
Charon


Podcast Direction에서 이미 생성된
Dialogue Beat를 기반으로 production speech segment를 만든다.


Podcast 핵심:

자연스러운 두 사람의 대화
짧은 turn-taking
질문/반응
재진술
구체적 예시
listener participation
필요할 때 vocabulary recap


금지:

PODCAST 안에 EDUCATION narrator를 별도로 끼워 넣는 것.

금지:

CLIP_ANALYSIS 문법을 자동 혼합하는 것.


==================================================
22. Podcast Pause / 말토막 시각화
==================================================

Podcast에서는 자연스러운 TTS pause가 중요한 production signal이다.

Speech Segment에:

pause_after_ms
pause_visual_behavior
sync_required
highlight_mode

를 저장한다.


향후 Renderer에서:

말하는 동안:
karaoke highlight 진행
waveform/ripple 활성

짧은 pause:
highlight 정지
waveform 축소/정지

생각 pause:
THINKING_DOTS 가능

다음 화자:
speaker indicator 전환

이 가능하도록 계획한다.


하지만 11단계에서는 실제 animation을 만들지 않는다.


==================================================
23. Visual Spec
==================================================

각 Block에 semantic visual plan을 만든다.

예:

{
  "primary_visual_type": "PHONEME_SEQUENCE",
  "content": ["B", "/b/", "A", "/æ/", "G", "/g/"],
  "progressive_reveal": true,
  "answer_hidden_until_attempt": false
}

CAP:

{
  "primary_visual_type": "QUESTION",
  "content": ["CAP"],
  "answer_hidden_until_attempt": true
}


실제:

font size
pixel
x/y
color
animation library

등은 아직 결정하지 않는다.


==================================================
24. Caption Spec
==================================================

Caption의 의미만 정의한다.

예:

caption_mode:

FULL_NARRATION
KEY_PHRASE
TARGET_ENGLISH
BILINGUAL
NONE


highlight_mode:

WORD
PHRASE
NONE


한국어 근사 발음이 표시되는 경우:

approximation_label_required = true

로 한다.

즉 시청자가 한국어 근사 표기를
영어 정답 발음으로 오해하지 않도록 한다.


==================================================
25. Replay Group
==================================================

같은 원어민 발화 또는 EN_NATIVE 발음을
반복 청취시키는 경우:

replay_group

을 사용한다.

예:

replay_group:
"RG01"

original:
RG01 occurrence 1

analysis 후:
RG01 occurrence 2


같은 음성을 다시 생성해야 한다는 의미가 아니라
향후 Asset Generator가 동일 asset 재사용 여부를 판단할 수 있게 한다.


==================================================
26. Timeline Event 구조
==================================================

각 production block은 ordered timeline event를 가진다.

예:

[
  {
    "event_order": 1,
    "type": "SPEECH",
    "speech_asset_id": "SP001"
  },
  {
    "event_order": 2,
    "type": "VISUAL",
    "visual_role": "TARGET_WORD"
  },
  {
    "event_order": 3,
    "type": "PAUSE",
    "duration_ms": 3000,
    "pause_visual_behavior": "THINKING_DOTS"
  },
  {
    "event_order": 4,
    "type": "SPEECH",
    "speech_asset_id": "SP002"
  }
]


허용 event type:

SPEECH
SOURCE_CLIP
VISUAL
CAPTION
PAUSE
REPLAY
BLOCK_TRANSITION


실제 frame number는 만들지 않는다.


==================================================
27. Duration 처리
==================================================

실제 TTS audio가 아직 없기 때문에
정확한 duration이라고 주장하지 않는다.

estimated_duration_seconds만 계산한다.

기존 script_writer의 deterministic duration estimation을
재사용할 수 있으면 재사용한다.

중복 공식은 만들지 않는다.


원본 Clip은 실제 boundary duration:

focus_out - focus_in

또는 context boundary를 기준으로 계산 가능하다.


==================================================
28. Viewer Action 보호
==================================================

09 → 10에서 보존된 viewer_action을
11에서도 절대 잃으면 안 된다.

특히:

viewer_action 존재
thinking_time_seconds > 0

이면

timeline에 반드시 해당 PAUSE가 있어야 한다.


그리고:

answer/reveal speech

가 PAUSE보다 먼저 나오면 Integrity fail.


==================================================
29. Content Required 보호
==================================================

09 required_content가
Production Plan에서 사라지면 안 된다.

각 Block의 required_content가:

speech
visual
clip
caption

중 최소 하나에서 실제로 구현되었는지 추적한다.

coverage mapping을 만든다.

예:

required_content_coverage:

{
  "BAG를 예시로 사용": ["VISUAL:V03", "SPEECH:SP05"],
  "B /b/, A /æ/, G /g/ 음소 제시":
      ["SPEECH:SP06", "SPEECH:SP07", "SPEECH:SP08"]
}

phoneme_explanation_safe
example_scope_safe

의 철학을 유지한다.

"BAG = 백"

같은 고정 등가를 만들면 안 된다.


KO_PRONUNCIATION_GUIDE가 존재하더라도:

EN_NATIVE와
KO_PRONUNCIATION_GUIDE를
동일 asset으로 취급하지 않는다.

Clip boundary는 10단계 값을 변경하지 않는다.

11단계가 임의 timestamp를 새로 찾지 않는다.


==================================================
32. Asset Deduplication
==================================================

동일한 EN_NATIVE target이 여러 번 필요한 경우
무조건 새 asset을 만들지 않는다.

같은:

speech_mode
voice
source_text
delivery intent

라면 동일 speech asset 재사용 가능.


단:

교육적으로 slow demonstration과
natural pronunciation이 다른 경우에는
별도 asset으로 둘 수 있다.

예:

BAG natural
BAG deliberate demonstration

은 별도.
