# 08. YouTube 영상 제작 설계

현재 프로젝트의 05 Topic Candidate,
06 Click Analysis,
07 Title & Thumbnail Strategy 결과를 이용해서

선정된 Title × Thumbnail Package를
실제로 제작 가능한 YouTube 영상 설계안으로 변환하는 기능을 구현해줘.


==================================================
전체 흐름에서 현재 위치
==================================================

시청자 조사
→ 주제 후보 여러 개
→ 클릭 이유 확인
→ 제목/썸네일 먼저
→ 영상 제작 설계   ← 현재 단계
→ 대본 작성
→ 영상 제작
→ 업로드
→ 성과 데이터 분석
→ 다음 주제 결정


완료 상태:

01 시장조사 시스템 구축
02 시장조사 신뢰도 개선
03 최종 검증
04 전체 시장조사
05 주제 후보 선정
06 클릭 이유 분석
07 제목/썸네일 전략


이번 단계의 목적은:

"제목을 정했으니 바로 대본을 써라"

가 아니다.


Title + Thumbnail이 시청자에게 한 약속을 분석하고,

그 약속을 실제 영상이 어떻게 지킬 것인지

영상의:

- 핵심 질문
- 핵심 답변
- 학습 목표
- Hook
- 설명 순서
- 예시
- 섹션
- 시청 유지 장치
- Shorts 추출 지점

까지 설계하는 것이다.


대본 전체 작성은 다음 단계에서 한다.


==================================================
1. Source of Truth
==================================================

다음을 우선 사용한다.

- content_packages
- click_analysis_topics
- click_analysis_videos
- topic_candidates
- video_keyword_matches
- videos
- channel config

리포트:

- reports/content_packages_YYYY-MM-DD.md
- reports/click_analysis_YYYY-MM-DD.md
- reports/topic_candidates_YYYY-MM-DD.md


가장 최신 데이터를 사용한다.


==================================================
2. 제작 대상 선정
==================================================

07의 실제 제작 검토 후보 중
선택된 Package를 대상으로 한다.


현재 우선 제작 대상:

Title:

왜 알파벳 이름을 다 아는데
3글자 단어도 바로 안 읽힐까?


Thumbnail:

B-A-G
비-에이-지? NO


Topic:

알파벳 이름만 아는 초보자가
자음과 단모음을 조합해
처음 보는 3글자 단어를 바로 읽는 방법


현재 근거:

Topic Candidate Score: 80.5
Click Evidence Score: 76.5
Package Score: 89.9
Brand Fit: high


단:

DB에서 명시적으로 제작 대상으로 선택된
Package가 존재한다면 그것을 source of truth로 사용한다.

없다면 07의 실제 제작 검토 후보 #1을 사용한다.


==================================================
3. 매우 중요한 설계 원칙
==================================================

영상의 출발점은 "가르치고 싶은 지식"이 아니다.

다음에서 출발한다.

TITLE PROMISE
+
THUMBNAIL PROMISE
+
VIEWER PROBLEM


즉:

시청자가 제목과 썸네일을 보고
무엇을 기대해서 클릭했는가?

를 먼저 정의한다.


그 기대를 영상 마지막까지
반드시 해결해야 한다.


==================================================
4. Viewer Contract
==================================================

각 영상마다 viewer_contract를 만든다.


viewer_contract에는 최소:

viewer_problem
click_expectation
video_promise
expected_transformation

을 포함한다.


현재 영상 예:

viewer_problem:

알파벳 A, B, C 이름은 알고 있지만
BAG 같은 간단한 단어를 보면
B-A-G를 각각 알파벳 이름으로 읽으려 해서
단어 소리로 조합하지 못한다.


click_expectation:

"왜 알파벳을 아는데도
단어를 못 읽는지 알고 싶다."


video_promise:

"알파벳 이름과 글자가 단어 안에서 내는 소리는 다르며,
기초적인 자음 + 단모음 소리를 조합하면
간단한 CVC 단어를 읽기 시작할 수 있다는 원리를 이해한다."


expected_transformation:

영상 전:
B-A-G → 비 / 에이 / 지

영상 후:
B → /b/
A → /æ/
G → /g/

→ BAG


중요:

영상이 실제로 보장할 수 없는 결과를
viewer_contract에 넣지 않는다.


==================================================
5. 제목/썸네일 약속 검증
==================================================

영상 설계 전에:

promise_feasibility

를 검사한다.


값:

- strong
- acceptable
- risky


확인:

1. 영상 내용으로 제목의 질문에 답할 수 있는가?
2. 썸네일의 사례를 실제 본문에서 설명하는가?
3. 제목이 영상보다 과장되어 있지 않은가?
4. 초보자가 영상 후 실제로 작은 성공을 경험할 수 있는가?


risky라면:

제목을 자동으로 변경하지 않는다.

risk_reason을 보고한다.


==================================================
6. One Video = One Core Answer
==================================================

한 영상에서 너무 많은 것을 가르치지 않는다.


각 영상마다:

core_question

하나와

core_answer

하나를 만든다.


현재 예:

core_question:

"알파벳 이름을 아는데
왜 BAG 같은 단어를 바로 읽지 못할까?"


core_answer:

"알파벳 이름과 단어 안에서 사용하는 기본 소리는 다르며,
단어를 읽을 때는 글자 이름이 아니라
각 글자의 소리를 연결해야 하기 때문이다."


영상 전체는 이 답을 증명하는 구조로 만든다.


==================================================
7. Learning Objective
==================================================

영상 종료 후 시청자가 할 수 있어야 하는 것을
1~3개로 제한한다.


현재 예:

1.
알파벳 이름과 알파벳 소리가
다르다는 것을 설명할 수 있다.

2.
간단한 자음 + 단모음 + 자음
구조를 이해할 수 있다.

3.
BAG, CAT, MAP 같은
기초 CVC 단어를 소리 조합으로 읽어볼 수 있다.


너무 넓은 목표를 넣지 않는다.


==================================================
8. Prerequisite
==================================================

이 영상을 이해하기 위해
시청자가 이미 알아야 할 것을 표시한다.


예:

- 영어 알파벳 모양을 어느 정도 안다.
- 알파벳 이름을 몰라도 영상 시청은 가능하다.
- 발음기호 지식 필요 없음.


prerequisite_level:

none
very_beginner
beginner
intermediate


현재 채널은 가능하면
very_beginner를 우선한다.


==================================================
9. Scope Boundary
==================================================

이번 영상에서 다룰 것과
다루지 않을 것을 명확하게 분리한다.


IN:

- letter name vs letter sound
- 기본 자음 소리
- 기본 단모음
- CVC 소리 조합
- 간단한 예시


OUT:

- 장모음 전체
- Magic E 상세
- 이중모음
- 묵음 전체
- 강세
- 슈와
- 예외 단어 전체
- IPA 전체


OUT 항목은
후속 콘텐츠 후보로 연결할 수 있다.


==================================================
10. Example Ladder
==================================================

예시는 무작위로 나열하지 않는다.

쉬운 것 → 원리 확인 → 작은 응용

순서로 설계한다.


example_ladder 구조:

Level 1:
소리 하나 확인

Level 2:
3개 소리 연결

Level 3:
비슷한 단어로 반복

Level 4:
처음 보는 단어 도전


현재 영상 예:

Level 1:

B → /b/
A → /æ/
G → /g/


Level 2:

B + A + G
→ BAG


Level 3:

CAT
MAP
DOG
SUN


Level 4:

기존 설명에 직접 사용하지 않은
새로운 CVC 단어 1~3개를 제시해서
시청자가 스스로 읽어보게 한다.


==================================================
11. 예시 정확성 검증
==================================================

영어 교육 콘텐츠이므로
예시가 원리를 잘못 가르치지 않도록 한다.


각 example에:

word
target_pattern
purpose
difficulty
exception_risk

를 저장한다.


exception_risk:

low
medium
high


가능하면 초보 영상에서는
low risk 예시를 우선한다.


불규칙 발음 단어를
규칙 예시처럼 사용하지 않는다.


==================================================
12. Hook 설계
==================================================

영상 첫 15~30초를 별도로 설계한다.


Hook의 목적:

제목/썸네일 약속을 즉시 이어받는 것.


긴 인사부터 시작하지 않는다.

채널 소개부터 시작하지 않는다.


권장 구조:

0~5초
문제 재현

5~15초
예상과 실제의 차이

15~30초
오늘 얻을 결과


현재 예:

화면:

B   A   G


질문:

"B, A, G.
세 글자는 다 아는데
왜 BAG는 바로 안 읽힐까요?"


다음:

"B는 비,
A는 에이,
G는 지라고 읽으면
단어가 되지 않습니다."


다음:

"단어를 읽을 때 필요한 건
알파벳 이름이 아니라
글자가 내는 소리입니다."


이것은 설계 예시이며
최종 대본은 아니다.


==================================================
13. Hook 유형 taxonomy
==================================================

다음 고정 taxonomy를 사용한다.

- immediate_question
- misconception
- before_after
- quiz
- surprising_example
- demonstration
- result_preview
- problem_reenactment


primary_hook_type
secondary_hook_type

최대 2개.


현재 후보:

primary:
problem_reenactment

secondary:
demonstration


==================================================
14. 영상 구조
==================================================

Long-form 기준으로
5~8개의 section을 설계한다.


각 section:

section_number
section_goal
viewer_question
key_point
example
estimated_duration
retention_device


예:

Section 1
왜 알파벳을 아는데 못 읽을까?

Section 2
알파벳 이름과 소리는 다르다

Section 3
B-A-G를 실제 소리로 바꿔보기

Section 4
세 소리를 연결하는 방법

Section 5
CAT / MAP / DOG로 반복

Section 6
처음 보는 단어 퀴즈

Section 7
오늘 원리 정리 + 다음 단계


==================================================
15. 설명 순서
==================================================

설명은 가능하면:

문제
→ 관찰
→ 원리
→ 예시
→ 반복
→ 직접 시도
→ 정리

순서로 만든다.


정의부터 길게 설명하지 않는다.


나쁜 예:

"CVC란 Consonant Vowel Consonant의 약자로..."


좋은 예:

CAT
MAP
DOG

를 먼저 보여주고

"세 단어는 모두
자음 + 모음 + 자음 구조입니다."

처럼 사례 뒤에 용어를 붙인다.


==================================================
16. Retention Device
==================================================

각 section마다
시청 유지 장치를 최대 1개 지정한다.


taxonomy:

- open_loop
- quiz
- prediction
- contrast
- new_example
- visual_change
- mini_success
- misconception_correction
- next_question


억지 cliffhanger를 만들지 않는다.


예:

"그럼 처음 보는 MAP도
같은 방법으로 읽을 수 있을까요?"

→ prediction


==================================================
17. Mini Success
==================================================

왕초보 콘텐츠에서는
시청자가 영상 중간에

"어? 나도 읽었다."

를 경험하게 하는 것을 중요하게 본다.


mini_success_point를 최소 1개 설계한다.


예:

설명하지 않은 CVC 단어를 보여주고

2~3초 생각 시간

→ 소리 분리

→ 정답


이 지점을 영상의 핵심 학습 보상으로 본다.


==================================================
18. Audio-first 설계
==================================================

현재 채널 특성을 고려해
화면을 보지 않아도 핵심 설명을 따라갈 수 있게 한다.


각 section에:

audio_dependency
visual_dependency

를 표시한다.


값:

low
medium
high


가능하면 설명 자체는
audio_dependency 중심으로 이해 가능하게 만들고,

철자 비교/단어 퀴즈처럼
시각 정보가 반드시 필요한 부분만
visual_dependency = high로 둔다.


==================================================
19. 화면 설계
==================================================

복잡한 영상 제작을 기본값으로 하지 않는다.


가능하면:

- 단어 크게 표시
- 해당 글자 강조
- 소리 분리
- 화살표
- 간단한 색 강조
- 질문
- 정답 공개

중심으로 설계한다.


각 section:

visual_type

taxonomy:

- word_focus
- letter_highlight
- sound_build
- comparison
- quiz_card
- rule_card
- recap_card


==================================================
20. Shorts 추출 지점
==================================================

Long-form을 만든 뒤
억지로 Shorts를 만드는 것이 아니라

설계 단계부터
Shorts로 독립 가능한 부분을 찾는다.


최소 1개,
가능하면 2~3개.


각 shorts_candidate:

hook
question
example
payoff
source_section
estimated_duration


현재 예:

Shorts A:

"BAG를 비-에이-지라고 읽으면
왜 틀릴까요?"


Shorts B:

"CAT 처음 보는 사람도
이 세 소리만 알면 읽을 수 있습니다."


중요:

Shorts만 봐도 작은 답을 얻을 수 있어야 한다.


==================================================
21. 다음 영상 연결
==================================================

이번 영상에서 OUT으로 뺀 내용을 이용해
natural_next_topics를 만든다.


예:

CVC
↓
Magic E
↓
모음 소리 변화
↓
처음 보는 단어 읽기
↓
묵음
↓
강세


단:

다음 영상을 억지로 확정하지 않는다.

후보만 만든다.


==================================================
22. Channel Brand Fit
==================================================

영상 설계가 채널 철학과 맞는지 검사한다.


현재 채널 핵심:

- 왕초보 눈높이
- 이해 중심
- 영어 읽기/소리 원리
- 무작정 암기보다 원리
- 과장보다 납득
- 학습자와 함께 이해해가는 방식


brand_design_fit:

high
medium
low


low라면 이유를 표시한다.


==================================================
23. Content Integrity Check
==================================================

최종 설계 전에 검사한다.


1.
제목의 질문에 실제로 답하는가?

2.
썸네일 사례를 본문에서 실제로 다루는가?

3.
초보자가 이해하기 전에
전문용어부터 나오지 않는가?

4.
한 영상에 너무 많은 규칙을 넣지 않았는가?

5.
예시가 규칙과 맞는가?

6.
예외를 규칙처럼 가르치지 않는가?

7.
시청자가 직접 해보는 구간이 있는가?

8.
영상 마지막에 처음 질문이 해결되는가?


각 항목:

pass
warning
fail


fail이 있으면
ready_for_script = false


==================================================
24. Production Complexity
==================================================

실제 제작 난이도도 계산한다.


요소:

- 화면 수
- 필요한 단어 카드 수
- TTS/나레이션 분량
- 애니메이션 필요성
- 외부 클립 필요 여부
- 추가 자료 필요 여부


complexity:

low
medium
high


현재 채널에서는
가능하면 low~medium을 우선한다.


==================================================
25. 외부 영상 클립
==================================================

외부 YouTube/TikTok/Instagram/영화 클립은
이번 단계에서 필수 요소로 가정하지 않는다.


필요한 경우에만:

external_clip_needed = true

와

clip_purpose

를 표시한다.


예:

- 실제 원어민 발음 비교
- 실제 연결 발음 사례
- 분석 대상 발화


단순 장식용 클립은 추천하지 않는다.


저작권/플랫폼 사용 기준을
회피하는 설계를 하지 않는다.


==================================================
26. Production Blueprint Score
==================================================

영상 설계안에 0~100 점수를 계산할 수 있다.


Gemini가 최종 숫자를 직접 결정하지 않는다.


권장 요소:

Viewer Contract 충족도 25%
Core Answer 명확성 15%
Example Ladder 15%
Mini Success 10%
Retention Structure 10%
Brand Fit 10%
Production Feasibility 10%
Shorts Expandability 5%


단:

점수는 참고용이다.

점수만으로 제작 여부를 확정하지 않는다.


==================================================
