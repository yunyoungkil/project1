# 13-3A. Answer Reveal Policy Scene Scope 정합성 교정

## 0. 이번 작업의 목적

13-3 완료 보고에서 다음 의미 오류가 발견되었다.

현재 문제:

CB06 MINI_SUCCESS
- SP039::CONTEXTUAL_WORD(CAP) 사용
- answer_reveal_policy 있음
- 실제 PAUSE / ANSWER_REVEAL_BARRIER 있음
- 정상

CB07 RECAP
- 동일한 SP039::CONTEXTUAL_WORD(CAP) 재사용
- render_spec.scene.answer_reveal_policy가 잘못 채워짐
- 실제 Timeline에는 ANSWER_REVEAL_BARRIER 없음
- 13-3은 Timeline barrier만 신뢰하여 정상 처리

즉 현재 시스템에는 다음 구조적 문제점이 있다.

"이 Asset이 Mini Success 정답 Asset인가?"

라는 asset-scoped 판정이

"이 Scene에서 이 Asset이 reveal barrier 뒤에 공개되어야 하는 정답인가?"

라는 scene-scoped 의미를 대신하고 있다.

같은 CAP audio asset이:

CB06에서는 Mini Success 정답
CB07에서는 단순 RECAP 재사용

인데 asset identity만으로 판단하면서 CB07까지 answer_reveal_policy가 오염된다.

이번 단계의 목표는:

1. answer_reveal_policy를 Scene scope에 맞게 교정
2. CB06 Mini Success barrier는 완전히 보존
3. CB07 RECAP에는 잘못된 answer_reveal_policy가 생기지 않게 수정
4. asset-scoped pronunciation/review 정책은 건드리지 않음
5. Render Spec → Timeline → Scene Layout을 재생성하여 downstream 정합성 재검증
6. 13-4 진입 전에 semantic debt 제거

이번 작업은 디자인 단계가 아니다.

외부 API 호출 금지.
TTS 재생성 금지.
MP4 생성 금지.

==================================================
3. 문제의 의미를 명확히 분리하라
==================================================

다음 두 질문은 다른 질문이다.

A. Asset-level question

"이 Speech Asset이 어떤 Mini Success에서 정답으로 사용된 적이 있는가?"

B. Scene-level question

"이 Scene에서 이 정답/Asset이 viewer attempt + pause 뒤에 공개되어야 하는가?"

answer_reveal_policy는 B에 속한다.

따라서 A를 직접 사용해 B를 결정하면 안 된다.

is_mini_success_answer_asset()가 A 의미라면
함수 자체를 무리하게 B로 변경하지 말고 유지하는 것을 우선 검토한다.

필요하면 scene-scoped helper를 별도로 만든다.

예:

is_scene_mini_success_answer(...)
has_scene_answer_reveal_barrier(...)
build_scene_answer_reveal_policy(...)

실제 프로젝트 스타일에 맞는 최소 구조를 선택한다.


==================================================
4. 13-1 Render Spec에서 올바른 Scene Scope 정의
==================================================

13-1에서 answer_reveal_policy를 채우려면
현재 Scene 자체의 evidence가 있어야 한다.

최소 조건 후보:

- 현재 Content Block이 viewer attempt를 요구함
- explicit PAUSE가 존재함
- 현재 block 내부에 answer asset/text가 존재함
- answer가 PAUSE 이후에 위치함

또는 기존 09~11 단계의 명확한 Mini Success metadata가 있다면
그것을 재사용할 수 있다.

중요:

scene_role == MINI_SUCCESS만 보고 policy를 자동 생성하는 것도 충분한지 검토하라.

만약 scene_role 자체가 이미 정확하고 deterministic한 Mini Success 분류라면
해당 Scene 내부 answer + pause evidence와 함께 사용하는 것이 안전하다.

예시 개념:

scene_answer_reveal_policy = (
    scene_role == "MINI_SUCCESS"
    AND scene_has_attempt_requirement
    AND scene_has_pause
    AND scene_has_answer_after_pause
)

정확한 구현은 실제 구조를 조사해 결정한다.

6. CB07 기대 동작
==================================================

CB07은 RECAP이다.

- viewer attempt 없음
- Mini Success PAUSE 없음

또는 field 미설정.

Mini Success semantic을 상속하면 안 된다.

Asset
→ stable media identity

9. Upstream 12단계 helper 변경 원칙

만약 실제 조사 결과 helper 자체의 명칭/의미가 오해를 유발한다면
deprecation/rename은 별도 기술부채로 기록하고 이번에는 최소 수정만 한다.

다음을 모두 만족해야 완료다.

- Answer reveal policy가 asset identity가 아니라 Scene context 기준

- 같은 CAP Asset의 cross-scene 재사용 정상
- CB06 PAUSE 3000ms 보존

- asset-scoped Human Review helper 의미 불필요하게 변경하지 않음
- CAP fallback asset 불변
- BAG/MAP/BAT active asset 불변
- failed/rejected variant 미사용
- experimental variant 미사용
- Render Spec 재생성 성공

- 신규 테스트 PASS

이번 단계의 핵심 원칙:

"Asset은 미디어의 정체성을 가진다.
Reveal Policy는 Scene의 교육적 문맥을 가진다."

동일한 CAP audio asset이 CB06에서는 정답이고
CB07에서는 복습 자료일 수 있다.

따라서 reveal policy는 Asset으로부터 상속되는 속성이 아니라
Scene binding에서 결정되는 contextual semantic이어야 한다.
