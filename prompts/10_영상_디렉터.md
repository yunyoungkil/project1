# 10단계: Video Director 구현

현재 프로젝트의 09-3 단계까지 구현이 완료되어 있다.

이번 작업의 목적은 09단계가 생성한 포맷 중립 Content Script를 읽어,
실제 영상의 제작 포맷과 Content Block별 연출 방향을 결정하는
새로운 10단계 Video Director를 구현하는 것이다.

중요:
이번 단계는 영상을 렌더링하는 단계가 아니다.
특정 편집 도구를 선택하는 단계도 아니다.

09 = WHAT TO TEACH
10 = HOW TO PRESENT IT
11 이후 = HOW TO PRODUCE IT

이 책임 경계를 절대 무너뜨리지 마라.


==================================================
0. 기존 시스템 보호 원칙
==================================================

기존 01~09-3 구현을 먼저 충분히 읽고 구조를 파악한 뒤 작업하라.

특히 다음 파일/구조를 먼저 확인하라.

- research/db.py
- research/script_writer.py
- research/production_blueprint.py
- research/cli.py
- config/research_config.yaml
- tests/
- video_scripts
- content_blocks_json
- ready_for_direction
- LEARNING_FUNCTIONS
- RETENTION_DEVICES
- media_affinity
- 기존 Integrity Check 17개

기존 함수/필드/CLI를 삭제하거나 의미를 변경하지 마라.

09-3의 기존 Integrity Check 17개를 수정하지 마라.

09의 Content Script를 10에서 다시 작성하거나 수정하지 마라.

10은 09 산출물을 READ-ONLY source로 사용한다.

기존 테스트가 깨지면 안 된다.


==================================================
1. 10단계의 최종 책임
==================================================

10단계 Video Director는 다음 질문에 답한다.

1. 이 Content Script에 가장 적합한 영상 포맷은 무엇인가?
2. 왜 그 포맷인가?
3. 각 Content Block은 어떤 방식으로 전달해야 하는가?
4. 실제 원본 Clip이 필요한가?
5. Clip이 필요하지만 적합한 Clip을 확보하지 못하면 어떻게 fallback하는가?
6. 다음 Production Planning 단계가 실행할 수 있을 정도로 충분한 Direction 정보가 존재하는가?

최종 포맷 taxonomy는 정확히 다음 4개만 허용한다.

EDUCATION
CLIP_ANALYSIS
HYBRID
PODCAST

새로운 포맷을 임의로 추가하지 마라.


==================================================
2. 가장 중요한 포맷 관계
==================================================

EDUCATION과 CLIP_ANALYSIS는 독립적인 기본 포맷이다.

HYBRID는 새로운 제3의 연출 문법이 아니라:

EDUCATION + CLIP_ANALYSIS

의 조합이다.

단, 단순히 두 포맷을 섞었다고 HYBRID가 되는 것은 아니다.

같은 학습 목표를 두 방식이 서로 다른 역할로 보완해야 한다.

PODCAST는 독립 포맷이다.

PODCAST 안에 EDUCATION/CLIP_ANALYSIS/HYBRID를 섞지 마라.

Podcast는 Podcast 자체의 제작 문법을 가진다.


==================================================
3. 10단계 내부 구조
==================================================

논리적으로 다음 구조를 구현하라.

10A Format Director
10B Source Clip Analyzer
10C Final Director
10D Block Director

필요하다면 하나의 모듈 안에 구현해도 되고,
책임 분리가 더 안전하다면 여러 모듈로 나눠도 된다.

기존 프로젝트 스타일을 우선하라.


==================================================
4. 10A — Format Director
==================================================

09의 Content Script와 Content Blocks를 읽고
preferred_format을 결정한다.

단순한 media_affinity 점수 합산만으로 결정하지 마라.

다음 Gate 순서를 기본 의사결정 구조로 사용하라.


-------------------------
Gate 1: Podcast Necessity
-------------------------

질문:

"이 콘텐츠의 핵심 가치가 설명/시연보다
두 사람의 자연스러운 대화를 따라가며
경험·조언·사례·공감·발견을 얻는 데 있는가?"

강한 신호:

- dialogue
- storytelling
- reflection/advice 성격
- 경험 공유
- 관점 교환
- 질문과 반응으로 이해가 깊어지는 주제

단순히 dialogue affinity가 high라는 이유만으로
PODCAST를 선택하면 안 된다.

예:

영어 공부 습관
영어 공부 순서
머릿속 번역을 줄이는 방법
영어 공부를 포기하지 않는 방법

등은 Podcast 적합성이 높을 수 있다.


----------------------------------
Gate 2: Authentic Evidence Necessity
----------------------------------

질문:

"실제 원어민/영화/실제 발화 Clip을 경험하지 않으면
Viewer Problem의 핵심을 제대로 체감하기 어려운가?"

YES라면 CLIP 계열 후보로 간다.

예:

"왜 Did you가 디쥬처럼 들릴까?"
"왜 원어민의 What are you가 안 들릴까?"

실제 발화 자체가 학습 증거인 경우다.


------------------------------
Gate 3: Explanation Necessity
------------------------------

Clip이 필요한 경우 다시 판단한다.

실제 Clip 분석 자체가 중심이면:

CLIP_ANALYSIS

실제 Clip 경험과 체계적인 원리 설명/시각화가
둘 다 중요하면:

HYBRID


-------------------------
Gate 4: Education Default
-------------------------

위 조건이 강하지 않으면:

EDUCATION

을 기본값으로 한다.

EDUCATION은 실패 fallback이 아니다.

원리 이해 → 예시 → 적용 → Mini Success가
가장 적절한 콘텐츠의 정상 포맷이다.


==================================================
5. media_affinity 사용 원칙
==================================================

09의 기존 8개 media_affinity 신호를 그대로 사용한다.

- visualization
- real_world_clip
- dialogue
- audio_demonstration
- replay
- comparison
- interaction
- storytelling

taxonomy를 임의 변경하지 마라.

다음은 참고 신호이지 기계적 공식이 아니다.

Education signals:
- visualization
- comparison
- interaction
- audio_demonstration

Clip signals:
- real_world_clip
- replay
- audio_demonstration

Podcast signals:
- dialogue
- storytelling

HYBRID는 독립 점수 하나로 결정하기보다

"Clip necessity가 강한가?"
+
"Education necessity도 강한가?"

를 판단하는 것을 우선한다.

Gemini/LLM 의미 판단을 사용할 수 있지만
결정 근거를 구조화해서 저장해야 한다.


==================================================
6. Format Director 출력
==================================================

최소 다음 개념을 저장하라.

preferred_format
format_confidence
format_reason
clip_dependency
fallback_format
final_format_status

format_confidence는 최소:

low
medium
high

clip_dependency는 최소:

none
optional
required

개념을 구분할 수 있어야 한다.

예:

preferred_format: EDUCATION
format_confidence: high
clip_dependency: none
fallback_format: null

또는:

preferred_format: HYBRID
format_confidence: medium
clip_dependency: required
fallback_format: EDUCATION
final_format_status: pending_source_analysis

format_reason은 단순 문자열 하나보다
여러 이유를 보존할 수 있는 구조가 좋다.


==================================================
7. 10B — Source Clip Analyzer
==================================================

매우 중요하다.

Source Clip Analyzer는
CLIP_ANALYSIS 또는 HYBRID에 실제 Clip이 필요한 경우에만 사용한다.

그리고 Clip의 검색 범위는:

"사용자가 제공한 원본 영상 파일 내부"

로 제한한다.

인터넷에서 임의의 YouTube/TikTok/영화 영상을
자동 검색하는 기능을 이번 단계에서 만들지 마라.

사용자가 원본 영상 하나를 제공하면
그 원본 안에서 가장 적합한 구간을 찾아야 한다.


==================================================
8. Source Clip Analyzer 기술 구조
==================================================

실제 구현 가능한 범위에서 다음 정보 구조를 준비하라.

source video
→ audio/transcript
→ timestamp
→ utterance/segment
→ pause/silence boundary
→ 필요 시 speaker information
→ Content Block semantic matching
→ Clip Candidate

단, 현재 프로젝트에 transcript/ASR/word timestamp 인프라가 없다면
이번 작업에서 거대한 외부 인프라를 새로 만들지 마라.

중요 원칙:

"없는 인프라를 가짜로 구현하지 않는다."

필요하면 Source Clip Analyzer를
입력 인터페이스 + candidate scoring + boundary logic 중심으로 구현하고,

실제 transcript/timestamp 공급은
후속 asset preparation 단계와 연결 가능하도록 설계하라.

어떤 부분이 실제 구현됐고
어떤 부분이 future dependency인지 보고서에 명시하라.


==================================================
9. Clip Candidate 탐색 철학
==================================================

너무 엄격한 Hard Gate를 만들지 마라.

좋은 Clip을 찾을 가능성을 높이기 위해:

Candidate Generation은 넓게,
Selection은 점수 기반으로 한다.

Hard Fail은 최소한으로 제한한다.

예:

- 분석 대상 발화를 특정할 수 없음
- Content Block과 사실상 관계없음
- 음성이 분석 불가능한 수준
- timestamp 자체가 유효하지 않음

그 외에는 후보로 유지하고 Soft Score로 평가한다.


==================================================
10. Clip Score
==================================================

초기 기본 점수는 다음을 사용한다.

Learning Match             30%
Phenomenon Clarity         25%
Replay Value               20%
Context Independence       15%
Audio Usability            10%

Clip Score:

0.30 * LearningMatch
+ 0.25 * PhenomenonClarity
+ 0.20 * ReplayValue
+ 0.15 * ContextIndependence
+ 0.10 * AudioUsability

각 sub-score는 0~100으로 정규화한다.

초기 grade:

85~100 = STRONG
70~84  = GOOD
55~69  = USABLE
<55    = WEAK

이 threshold는 config로 분리하는 것을 우선 검토하라.

magic number를 코드 여러 곳에 흩뿌리지 마라.


==================================================
11. Clip Role
==================================================

각 Clip Candidate에는
"왜 이 Clip을 사용하는가"가 있어야 한다.

초기 taxonomy:

HOOK
EVIDENCE
ANALYSIS_TARGET
EXAMPLE
PRACTICE
REPLAY

하나의 Clip이 필요하다면 여러 역할을 가질 수 있는지
기존 코드 스타일과 실제 사용성을 보고 결정하되,
최소한 primary role은 명확해야 한다.


==================================================
12. FOCUS / CONTEXT Clip
==================================================

Clip boundary를 하나만 저장하지 마라.

가능하면 두 종류를 구분한다.

FOCUS CLIP:
실제로 분석할 정확한 발화 구간

CONTEXT CLIP:
앞뒤 자연스러운 맥락을 약간 포함한 구간

예:

context_in: 191.80
context_out: 198.40

focus_in: 194.21
focus_out: 196.73

이를 통해 후속 제작 단계가:

첫 재생 = CONTEXT
분석 = FOCUS
slow replay = FOCUS
최종 확인 = CONTEXT

같은 결정을 할 수 있다.

정확한 padding/boundary 계산은 기술적으로 안전하게 구현하라.

영상 시작 < 0 또는 영상 길이 초과가 발생하면 안 된다.


==================================================
13. 10C — Final Director
==================================================

Format Director의 preferred_format과
실제 Clip availability를 합쳐 final_format을 결정한다.

중요:

CLIP_ANALYSIS/HYBRID는
"Clip을 찾기 전"과 "찾은 후"의 상태가 다를 수 있다.


Case A:
HYBRID 추천
+ 충분히 좋은 Clip 확보

→ HYBRID


Case B:
CLIP_ANALYSIS 추천
+ STRONG/GOOD Clip 확보

→ CLIP_ANALYSIS


Case C:
CLIP_ANALYSIS 추천
+ 약한 Clip만 존재

→ CLIP_ANALYSIS를 억지 유지하지 마라.

HYBRID 또는 EDUCATION으로 재판단한다.


Case D:
HYBRID 추천
+ 일부 Block만 좋은 Clip 존재

→ HYBRID 유지 가능

Clip이 없는 Block만 EDUCATION delivery로 대체한다.


Case E:
적합 Clip 없음

→ EDUCATION fallback


절대 원칙:

"Asset이 없다고 학습 목적을 삭제하지 않는다."

Content Block의 educational purpose는 항상 보존한다.


==================================================
14. Block-level Delivery Mode
==================================================

각 Content Block마다 delivery_mode를 결정한다.

최소 허용:

EDUCATION
CLIP_ANALYSIS

PODCAST 영상이면 Podcast 전용 Block direction을 사용한다.

HYBRID 영상의 Block은:

EDUCATION
CLIP_ANALYSIS
또는 양쪽 기능이 정말 필요한 경우
명확한 combined direction

으로 표현할 수 있다.

단, 불필요하게 모든 Block을 combined로 만들지 마라.


==================================================
15. 10D — Block Director
==================================================

09의 Content Block을
실제 제작 방향 정보로 변환한다.

반드시 보존해야 하는 입력:

content_block_id
section_number
learning_function
purpose
required_content
importance
prerequisite_blocks
viewer_action
thinking_time_seconds
retention_intent
media_affinity
base_narration

10은 이 값을 수정하지 않는다.

별도의 direction object를 생성한다.

==================================================
17. EDUCATION 제작 문법
==================================================

EDUCATION의 기본 학습 경험:

PROBLEM
→ EXPLAIN
→ DEMONSTRATE
→ PRACTICE
→ MINI SUCCESS
→ RESOLVE

Content에 따라 일부는 압축 가능하다.

반드시 지켜야 할 원칙:

- 한 번에 핵심 개념 하나
- 시각화는 의미 전달을 위해 사용
- 예시는 쉬운 것에서 어려운 것으로
- 직접 해볼 수 있는 순간에는 정답 선공개 금지
- 최소 하나의 적용/성공 경험
- 마지막에는 처음의 질문/문제를 해결

하지 말아야 할 것:

- 슬라이드 낭독
- narration 전체를 화면 자막으로 그대로 복제
- 의미 없는 Zoom/회전/튀는 애니메이션
- 한 화면에 여러 규칙 과다 제시
- 어려운 전문용어부터 시작
- 학습 효과 과장
- 이유 없는 외부 Clip 삽입


==================================================
18. CLIP_ANALYSIS 제작 문법
==================================================

핵심 경험:

HEAR
→ QUESTION
→ ISOLATE
→ ANALYZE
→ PRACTICE
→ REPLAY
→ RECOGNIZE

시청자는 분석 전/후 같은 실제 발화를
다르게 듣는 경험을 해야 한다.

반드시:

- 분석 전 원본 경험
- 질문
- Focus Clip
- 실제 발화 분석
- 시청자 참여
- 분석 후 Replay

가능하면 Mini Success는:

"처음에는 안 들렸지만 이제 들린다."

가 되도록 한다.

하지 말아야 할 것:

- Clip을 단순 B-roll로 사용
- 긴 원본을 불필요하게 재생
- Clip과 무관한 규칙 삽입
- 원본에서 실제로 일어나지 않은 발음 현상 주장
- 맥락 왜곡
- 분석 전에 정답 전체 공개
- 약한 Clip을 억지로 채택


==================================================
19. HYBRID 제작 문법
==================================================

HYBRID의 핵심 루프:

REALITY
→ EXPLANATION
→ PRACTICE
→ REALITY

실제 영어 경험과 원리 설명이
같은 학습 목표를 서로 다른 역할로 지원해야 한다.

각 Block은 필요에 따라:

CLIP
EDUCATION
CLIP + EDUCATION

중 하나가 될 수 있다.

하지 말아야 할 것:

- 영상이 지루해 보인다는 이유로 Clip 삽입
- 모든 Block에 Clip 강제
- Clip과 Education이 같은 내용을 중복 설명
- Clip 부족인데 HYBRID 강제
- 지나친 포맷 전환

Clip이 없는 Block은
학습 목적을 유지한 채 EDUCATION으로 대체한다.


==================================================
20. PODCAST 제작 문법
==================================================

PODCAST는 다른 세 포맷과 분리한다.

목표:

"두 사람이 영어/학습 주제에 대해 자연스럽게 이야기하는 자리에
청취자가 같이 앉아 있는 경험"

09 Content Block을 Dialogue Beat로 변환한다.

큰 흐름의 기본 참고 구조:

OPEN
→ VIEWER PROBLEM
→ NATURAL DIALOGUE
→ DISCOVERY
→ PRACTICAL STRATEGY
→ LISTENER PARTICIPATION
→ NEXT IDEA
→ optional WORD TOUR
→ RECAP
→ ONE SMALL ACTION
→ SIGN-OFF

모든 Podcast가 이 순서를 기계적으로 전부 가져야 하는 것은 아니다.

Content Script 목적을 우선한다.


==================================================
21. Podcast Micro Rhythm
==================================================

자연스러운 대화 단위의 기본 문법:

STATEMENT
→ REACTION
→ QUESTION
→ EXPLANATION
→ EXAMPLE
→ CONFIRMATION

이를 기계적으로 반복하지 마라.

목적은 "대화처럼 느껴지는 교육"이지
정형화된 Q&A 생성이 아니다.

두 화자의 역할/성격은 구분되어야 한다.

예:

Host A:
learner-facing / curious / relatable

Host B:
explanatory / experienced / clarifying

그러나 모든 Episode에 같은 캐릭터를 강제하지 마라.

향후 Character/Voice 설정과 분리 가능한 구조로 설계한다.


==================================================
22. Podcast 금지사항
==================================================

다음을 방지하라.

- 한 화자의 장시간 독백
- 다른 화자가 "맞아요"만 반복
- 두 화자의 말투/역할이 사실상 동일
- 모든 문장을 질문/답변으로 억지 분리
- 의미 없는 Wow / Amazing / Exactly 남발
- Podcast 도중 갑자기 강의 슬라이드 영상으로 변환
- 영상 길이를 늘리기 위한 반복
- 본문에 없는 어려운 단어를 Word Tour용으로 억지 삽입

Word Tour를 사용한다면
실제 본문에서 등장한 표현만 대상으로 한다.


==================================================
23. Podcast Pause / Visual State
==================================================

10단계에서는 특정 렌더러 명령을 만들지 않는다.

대신 후속 제작 단계가 사용할 수 있도록
다음 semantic direction을 표현할 수 있어야 한다.

speaker_active
speaker_change
speech_active
pause
thinking_pause
karaoke_hold
wave_active
wave_reduced
optional_ellipsis

핵심 원칙:

"오디오가 화면 상태를 결정한다."

말하는 동안:
- active speaker
- karaoke progression
- wave/ripple active

짧은 pause:
- karaoke hold
- wave reduce/stop

화자 변경:
- active speaker transition

생각 pause:
- 필요한 경우만 ellipsis

모든 pause에 "..."를 넣으면 안 된다.

이번 단계에서 실제 waveform animation이나
pixel animation을 구현하지 마라.


==================================================
24. 공통 Director 원칙
==================================================

모든 포맷에 다음 원칙을 적용한다.


A. Content Purpose First

production gimmick보다
Content Block purpose가 우선한다.


B. Required Content Preservation

required_content를 연출 때문에 잃지 않는다.


C. Viewer Action Preservation

viewer_action이 있으면
Direction Plan에도 실제 행동으로 반영한다.


D. Thinking Time Preservation

thinking_time_seconds > 0이면
후속 제작 단계가 그 시간을 제거할 수 없도록
direction에 명시한다.


E. Retention Intent Preservation

retention_intent의 type/purpose를
실제 direction으로 번역한다.


F. Format Neutral Source Protection

09 Content Script 자체는 수정하지 않는다.


G. Audio-first Compatibility

채널 특성상 화면을 보지 않아도
핵심 교육 논리를 따라갈 수 있어야 한다.

단, Clip Analysis처럼 실제 영상/음성 경험이 학습 대상인 경우는
그 특성을 direction에 명시한다.

28. Integrity Checks
==================================================

10단계 전용 Integrity Check를 새로 만든다.

09의 기존 17개는 그대로 유지한다.

최소 다음 검증을 포함하라.


1. valid_format

최종/선호 포맷이 허용 taxonomy 안에 있는가?


2. content_blocks_preserved

09의 direction_eligible Content Block이
누락되지 않았는가?


3. required_content_preserved

중요 required_content가 direction 과정에서
삭제되지 않았는가?


4. viewer_action_preserved

viewer_action이 있는 Block에서
viewer interaction이 사라지지 않았는가?


5. thinking_time_preserved

thinking_time_seconds > 0인 Block에서
시간이 보존되는가?


6. retention_intent_preserved

retention intent가 direction에 반영되는가?


7. clip_dependency_consistent

EDUCATION인데 이유 없이 required Clip dependency가 생기거나,
CLIP_ANALYSIS인데 필요한 Clip 상태가 무시되지 않는가?


8. clip_boundary_safe

focus/context timestamp가 유효하고
focus가 context 범위 안에 있는가?


9. weak_clip_not_forced

WEAK Clip 때문에 CLIP_ANALYSIS/HYBRID가
억지 유지되지 않는가?


10. fallback_preserves_learning

Clip fallback이 발생해도 해당 Content Block이
삭제되지 않는가?


11. podcast_isolation_safe

PODCAST가 다른 포맷의 production grammar와
무분별하게 섞이지 않는가?


12. no_renderer_instruction

10단계 산출물에 특정 렌더러/픽셀/폰트/색상/easing 등의
실행 명령이 들어가지 않는가?


13. source_script_unchanged

10 실행 전후 09 source row가 변경되지 않았는가?


필요하면 의미 있는 추가 체크를 만들 수 있다.

29. Ready Gate
==================================================

새 source of truth:

ready_for_production_planning

YES 조건:

- 10단계 critical Integrity Check 전부 pass
- final_format이 결정됨
- 모든 direction_eligible Content Block에 direction 존재
- 필요한 viewer_action/thinking_time 보존
- Clip이 필수인 final format이라면 실제 usable Clip 상태가 충족됨
  또는 안전한 fallback이 적용되어 final format이 재결정됨

단순 Director Score 하나만으로 YES를 만들지 마라.

Integrity Gate가 우선이다.

34. BAG 실데이터 Acceptance Test
==================================================

현재 최신 09-3 BAG/BAT/MAP/CAP Content Script를
실데이터 acceptance case로 사용하라.

정상적인 결과는 대략 다음 성격이어야 한다.

preferred/final format:
EDUCATION

clip_dependency:
none

이유:

- real_world_clip 의존도가 낮음
- visualization이 중요
- audio demonstration이 중요
- comparison/interaction이 중요
- BAG→BAT→MAP→CAP 단계적 원리 설명이 핵심

Block 방향은 대략:

CB01 → Problem Recognition
CB02 → Name vs Sound Contrast
CB03 → BAG Sound Blending Demonstration
CB04 → BAT Contrast/Demonstration
CB05 → MAP Guided Practice
CB06 → CAP Read-before-reveal Mini Success
CB07 → Recap / Next Question
CB08 → Resolution

정확한 wording을 hard-code하지 마라.

중요한 것은 의미 구조다.
