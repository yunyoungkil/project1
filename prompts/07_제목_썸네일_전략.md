# 07. YouTube 제목 · 썸네일 전략

현재 프로젝트의 05 Topic Candidate 결과와
06 Click Analysis 결과를 이용해서
실제 제작 후보의 "제목 + 썸네일 패키지"를 설계하고 비교해줘.

==================================================
전체 흐름에서 현재 위치
==================================================

시청자 조사
→ 주제 후보 여러 개
→ 클릭 이유 확인
→ 제목/썸네일 먼저   ← 현재 단계
→ 영상 제작
→ 업로드 데이터 분석
→ 다음 주제 결정


완료 상태:

01 시장조사 시스템 구축
02 시장조사 신뢰도 개선
03 최종 검증
04 전체 시장조사
05 주제 후보 선정
06 클릭 이유 분석

이번 단계의 목적:

"무슨 영상을 만들까?"를 다시 조사하는 것이 아니다.

선정된 주제를 실제 YouTube에서 클릭 가능한 형태로
어떻게 패키징할 것인지 비교하는 단계다.


==================================================
1. 입력 데이터
==================================================

다음을 source of truth로 사용한다.

- topic_candidates
- click_analysis_topics
- click_analysis_videos
- video_keyword_matches
- videos
- title archetype 분석
- channel config
- reports/topic_candidates_YYYY-MM-DD.md
- reports/click_analysis_YYYY-MM-DD.md


새로운 YouTube 시장조사를 하지 않는다.

가능하면 새 YouTube API 호출 없이 수행한다.


==================================================
2. 기본 분석 대상
==================================================

06에서 07 단계로 넘긴 Topic을 기본 대상으로 한다.

현재 자동 선정 결과:

1.
영어 왕초보는 단어, 문법, 회화 중
첫 달에 무엇부터 시작해야 할까?

2.
알파벳 이름만 아는 초보자가
자음과 단모음을 조합해
처음 보는 3글자 단어를 읽는 방법

3.
사전 없이 처음 보는 영어 단어를
읽게 만드는 핵심 파닉스 규칙

4.
같은 알파벳 모음인데
단어마다 소리가 달라지는 이유

5.
노베이스 성인의 영어 공부 순서


그리고 비교군으로 다음 Listening Topic을 추가한다.

6.
아는 단어도 안 들리게 만드는
원어민의 연음·축약 법칙


단:

실제 DB의 최신 06 결과가 다르면
최신 결과를 우선한다.

Listening 비교군은
자동 순위를 왜곡하지 않고
별도 comparison candidate로 표시한다.


==================================================
3. 매우 중요한 원칙
==================================================

이번 단계에서

"좋은 제목 하나 만들어줘"

방식으로 처리하지 않는다.


각 Topic마다 여러 개의

TITLE × THUMBNAIL PACKAGE

를 만든다.


즉:

Topic
   ↓
Click Driver
   ↓
Packaging Angle
   ↓
Title
   +
Thumbnail
   ↓
Package 비교

구조로 처리한다.


==================================================
4. Topic과 Title을 구분
==================================================

Topic은 시청자가 가진 문제다.

Title은 그 문제를 클릭하게 만드는 표현이다.


예:

Topic:

영어는 왜 철자대로 읽히지 않는가


가능한 Title:

knife의 K는 왜 소리가 안 날까?
영어가 철자대로 안 읽히는 진짜 이유


즉 Topic 문장을 그대로 Title로 복사하지 않는다.


==================================================
5. Packaging Angle 생성
==================================================

각 Topic마다 최소 4개의 서로 다른
Packaging Angle을 만든다.


고정 Angle taxonomy:

1. problem
   시청자의 문제를 직접 보여줌

2. curiosity
   이유/반전/의문을 이용

3. result
   시청 후 얻을 결과를 강조

4. example
   구체적인 영어 단어/문장 사례

5. beginner_identity
   왕초보/성인 초보 등의 자기 인식

6. mistake
   흔한 실수 또는 잘못된 접근

7. contrast
   전/후 또는 예상/실제 대비

8. simplicity
   복잡한 것을 쉽게 이해한다는 약속


각 Package에는:

primary_angle
secondary_angle

을 저장한다.


==================================================
6. Click Driver 연결
==================================================

06에서 실제로 확인된 Click Driver를 사용한다.


예:

speed_convenience
beginner_identity
result_promise
curiosity_gap
one_solution
problem_recognition
specificity
social_proof
surprise
fear_or_failure


각 제목을 임의로 만들지 말고

Topic
+
실제 반복 Click Driver
+
Packaging Angle

을 이용한다.


==================================================
7. 제목 후보 생성
==================================================

각 Topic마다 최소 5개 제목 후보를 만든다.

6 Topic이면 최소 30개 제목이다.


제목끼리 단어만 조금 바꾸는 식으로 만들지 않는다.

나쁜 예:

영어 묵음은 왜 생길까?
영어 묵음은 왜 생기는 걸까?
영어 묵음이 생기는 이유는?


이것은 사실상 같은 제목이다.


좋은 방식:

A.
knife의 K는 왜 소리가 안 날까?
영어 묵음의 원리

B.
영어는 왜 써 있는 대로 읽으면 틀릴까?

C.
처음 보는 영어 단어,
이 글자는 읽지 마세요

D.
KNIFE를 '크나이프'라고 읽으면 안 되는 이유

처럼 클릭 이유 자체가 달라야 한다.


==================================================
8. 과장 방지
==================================================

경쟁 영상에서 자주 발견됐더라도
다음 표현을 무조건 복제하지 않는다.

- 무조건
- 100%
- 완벽
- 평생
- 이것만 알면 끝
- 99%가 모르는
- 충격
- 기적
- 1초 만에
- 무조건 됩니다


사용하려면 실제 영상 내용이
그 약속을 충분히 뒷받침해야 한다.

그렇지 않으면 penalty를 준다.


==================================================
9. 제목 독창성
==================================================

기존 Outlier 제목을 그대로 복사하지 않는다.

유사도를 검사한다.

기존 제목과 지나치게 비슷하면:

copy_risk = high

로 표시하고 최종 후보에서 제외한다.


구조를 참고하는 것은 허용한다.

문장을 복사하는 것은 금지한다.


==================================================
10. 썸네일 문구 생성
==================================================

각 제목마다 썸네일 문구를 만든다.

원칙:

- 짧게
- 한눈에 이해
- 제목 전체 반복 금지
- 핵심 단어 우선
- 가능하면 2줄 이내


권장:

2~6단어 정도


예:

Title:

knife의 K는 왜 소리가 안 날까?
영어 묵음의 원리


Thumbnail:

KNIFE
K는 어디 갔지?


또는:

읽으면
틀립니다


==================================================
11. 제목 × 썸네일 역할 분담
==================================================

각 Package를 다음 taxonomy로 분류한다.

- complementary
- curiosity_plus_answer
- problem_plus_solution
- setup_plus_payoff
- contrast
- duplicate
- unclear


duplicate는 penalty를 준다.


예:

나쁜 조합:

Title:
영어는 왜 철자대로 읽히지 않을까?

Thumbnail:
왜 철자대로 안 읽힐까?


좋은 조합:

Title:
영어는 왜 철자대로 읽히지 않을까?

Thumbnail:
KNIFE
K는 어디 갔지?


==================================================
12. 썸네일 Visual Concept
==================================================

단순 문구만 만들지 말고
실제 제작 가능한 visual concept도 생성한다.


각 Package:

thumbnail_text
visual_focus
layout
example_word
highlight_element


예:

thumbnail_text:
K는 어디 갔지?

visual_focus:
KNIFE 단어

layout:
중앙에 KNIFE 크게 표시

highlight_element:
K만 흐리게 또는 X 표시

secondary:
아래에 "나이프"


중요:

현재 채널에서 실제 제작 가능한
단순 자막/텍스트 중심 디자인을 우선한다.

복잡한 촬영이나
유명인 얼굴 의존 디자인을 기본으로 하지 않는다.


==================================================
13. 초보자 가독성
==================================================

채널 시청자가 영어 초보자라는 점을 반영한다.

영어 예시를 썸네일에 넣는 경우:

한눈에 읽기 어려운 긴 영어 문장을 피한다.

좋음:

KNIFE
CAKE
ABOUT
DID YOU


나쁨:

긴 영어 문장 전체


영어 예시는 클릭의 핵심 사례로만 사용한다.


==================================================
14. Package Score
==================================================

각 Title × Thumbnail Package에
0~100 점수를 계산한다.

Gemini가 최종 숫자를 직접 정하지 않는다.

가능하면 결정론적 코드로 계산한다.


권장 요소:

A. Viewer Problem 명확성 20%

B. Click Driver 일치도 20%

C. Curiosity / Result Strength 15%

D. Title × Thumbnail 역할 분담 15%

E. Channel Brand Fit 15%

F. Specificity 10%

G. Originality / Copy Safety 5%


과장 penalty:

-5 ~ -20


duplicate thumbnail penalty:

-10


copy_risk high:

최종 shortlist 제외


==================================================
15. Topic Score와 섞지 않는다
==================================================

다음 점수를 별도로 보여준다.

Topic Candidate Score
Click Evidence Score
Package Score


예:

Topic:
모음 소리 변화

Topic Candidate:
79.4

Click Evidence:
69.4

Package:
87


세 점수는 서로 다른 의미다.


==================================================
16. Package 비교
==================================================

각 Topic에서 TOP3 Package를 남긴다.

6 Topic이면 최대 18개 정도가 된다.


각 Package마다:

Topic
Title
Thumbnail text
Visual concept
Primary angle
Click driver
Title-thumbnail relationship
Brand fit
Copy risk
Package score


를 출력한다.


==================================================
17. 전체 TOP Package
==================================================

Topic별 TOP3와 별도로

전체 Package TOP10을 만든다.


하지만 같은 Topic이 TOP10을 독점하지 않도록 한다.

한 Topic당 최대 2개를 권장한다.


==================================================
18. 사람 검토용 질문
==================================================

최종 Package마다 사람이 판단할 수 있도록
다음 항목을 표시한다.


"이 제목을 보고 시청자가 무엇을 기대하는가?"

"썸네일을 1초 봤을 때 무엇이 궁금해지는가?"

"영상이 실제로 이 약속을 지킬 수 있는가?"

"우리 채널에서 자연스럽게 느껴지는가?"


==================================================
19. 제작 후보 선정
==================================================

07 마지막에는

"실제 제작 검토 후보"

3개를 선정한다.


중요:

Package Score 1~3위를
기계적으로 선정하지 않는다.


다음을 함께 고려한다.

- Topic Candidate Score
- Click Evidence Score
- Package Score
- Brand Fit
- 제작 난이도
- 현재 채널 콘텐츠와 연결성
- Long-form + Shorts 확장성


==================================================
20. Listening 비교군 처리
==================================================

Listening 비교군은 특별히 별도 표시한다.


질문:

"Reading 중심 후보들과 비교했을 때
Listening Topic도 충분히 강한 Package가 나오는가?"


만약:

Topic Score 강함
+
Click Evidence 충분
+
Package Score 높음
+
Brand Fit high

라면

자동 06 shortlist에 없었다는 이유만으로 제외하지 않는다.


반대로 Package가 약하면
정직하게 탈락시킨다.

까지만 한다.
