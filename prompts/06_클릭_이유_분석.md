# 06. YouTube 클릭 이유 분석

현재 프로젝트의 Topic Candidate 결과와 기존 YouTube 시장조사 DB를 이용해서,
다음 단계인 "제목/썸네일 전략"으로 넘길 후보를 선별할 수 있도록
실제 Outlier 영상의 클릭 이유를 분석해줘.

==================================================
전체 흐름에서 현재 위치
==================================================

시청자 조사
→ 주제 후보 여러 개
→ 클릭 이유 확인   ← 현재 단계
→ 제목/썸네일 먼저
→ 영상 제작
→ 업로드 데이터 분석
→ 다음 주제 결정


현재 완료 상태:

01 유튜브 시장조사 시스템 구축
02 시장조사 신뢰도 개선
03 최종 검증
04 전체 카테고리 시장조사
05 주제 후보 선정

05 결과에서 다음 단계 조사 대상으로 10개 주제가 선정되어 있다.

이번 단계에서는
"이 주제가 왜 좋은가?"를 다시 계산하는 것이 아니라

"실제 사람들이 왜 이 주제의 영상을 클릭했는가?"

를 확인한다.


==================================================
1. 입력 데이터
==================================================

가능하면 새 YouTube API 호출 없이
현재 DB와 기존 수집 데이터를 우선 사용한다.

활용 데이터:

- topic_candidates
- video_keyword_matches
- videos
- channels
- outlier_scores
- content_patterns
- topic_opportunities
- channel_baselines
- 기존 Weekly Report
- reports/topic_candidates_YYYY-MM-DD.md

05에서 선정한 "다음 단계로 넘길 후보"를 우선 분석 대상으로 한다.


==================================================
2. 분석 대상 Topic
==================================================

05의 shortlist 10개를 기본 대상으로 한다.

현재 후보 예:

1.
영어 왕초보는 단어, 문법, 회화 중 첫 달에 무엇부터 시작해야 할까?

2.
노베이스 성인이 영어 회화를 독학할 때 가장 효과적인 영역별 공부 순서는?

3.
알파벳 이름만 아는 초보자가 처음 보는 3글자 단어를 바로 읽는 방법은?

4.
같은 알파벳 모음인데 단어마다 소리가 완전히 달라지는 진짜 이유는?

5.
knife의 k는 왜 발음하지 않을까?
영어 철자와 발음이 따로 노는 이유

6.
사전 없이 처음 보는 영어 단어를 바로 읽게 만드는 핵심 파닉스 규칙은?

7.
외운 영어 단어를 다음 날 바로 까먹지 않고 장기 기억으로 남기는 복습법은?

8.
들으면 이해되는 영어가 왜 입 밖으로는 안 나올까?

9.
아는 단어도 안 들리게 만드는 원어민의 연음·축약 법칙은?

10.
스크립트를 보면 다 아는 쉬운 단어가 미드에서는 왜 전혀 안 들릴까?


단:
실제 topic_candidates 데이터가 이 목록과 다르면
DB의 최신 shortlist를 source of truth로 사용한다.


==================================================
3. 각 Topic별 대표 Outlier 수집
==================================================

각 Topic에 연결된 Outlier 영상을 최소 3개,
가능하면 5개 정도 선정한다.

대표 영상 선정 기준:

- 높은 opportunity_score
- 높은 outlier_ratio
- Viewer Problem과 직접 관련
- evidence_quality 우선순위:
  direct > adjacent > weak
- 서로 다른 채널을 우선
- 같은 영상 중복 최소화


중요:

Outlier 배수만 높은 밈/예능/연예인 Shorts 하나가
전체 분석을 대표하게 하지 않는다.

가능하면:

직접 교육 콘텐츠
+
인접 콘텐츠
+
높은 반응의 비교육 콘텐츠

를 구분해서 본다.


==================================================
4. 클릭 이유 분석의 핵심 질문
==================================================

각 영상마다 다음 질문에 답한다.

A. 시청자가 클릭 직전 어떤 문제를 느끼고 있었는가?

B. 제목은 그 문제를 어떤 표현으로 건드리는가?

C. 제목이 약속하는 결과는 무엇인가?

D. 제목에 호기심 gap이 있는가?

E. 제목이 구체적인가, 포괄적인가?

F. 제목에 다음 장치가 있는가?

- 왜
- 이유
- 이것만
- 끝
- 왕초보
- 실제
- 원어민
- 처음 보는
- 하지 마세요
- 몇 가지
- 숫자
- 시간 절약
- 손해 회피
- 실수 회피
- 반전
- 결과 약속

G. 제목의 핵심 emotion은 무엇인가?

예:
- 답답함
- 불안
- 호기심
- 안도감
- 기대
- 놀람
- 손해 회피
- 자존심
- 자신감


==================================================
5. 썸네일 분석
==================================================

가능한 경우 thumbnail_url을 이용해 썸네일 정보를 분석한다.

단순 OCR 프로젝트를 새로 만들지 않는다.

이미지 분석이 가능한 기존 방식이 있으면 활용하고,
없다면 제목/metadata 중심 분석으로 진행하고
썸네일 분석 불가 상태를 명확하게 표시한다.

각 썸네일에서 확인:

- 핵심 문구
- 단어 수
- 문제 제기인지
- 결과 약속인지
- 전/후 비교인지
- 질문인지
- 숫자 사용 여부
- 영어 단어 예시 사용 여부
- 얼굴/표정 사용 여부
- 시각적 대비
- 제목과 같은 말을 반복하는지
- 제목과 역할을 나누는지


가장 중요한 항목:

title_thumbnail_relationship

값 예:

- duplicate
- complementary
- curiosity_plus_answer
- problem_plus_solution
- setup_plus_payoff
- unclear


==================================================
6. 제목과 썸네일의 역할 분담
==================================================

잘 된 영상에서

제목:
문제를 설명

썸네일:
결과를 약속

또는

제목:
호기심 생성

썸네일:
구체적 사례 제시

같은 역할 분담이 있는지 분석한다.


예:

제목:
"영어는 왜 철자대로 읽히지 않을까?"

썸네일:
KNIFE
K는 어디 갔지?

처럼 서로 같은 문장을 반복하지 않고
클릭 이유를 강화하는 구조를 찾는다.


==================================================
7. 영상 첫 30초 분석
==================================================

가능한 경우 영상 metadata/description/기존 transcript 데이터가 있다면
첫 30초 Hook 구조를 분석한다.

새로운 transcript API나 대량 외부 호출을
이번 단계에서 임의로 추가하지 않는다.

현재 데이터로 확인 불가능하면:

hook_data_status = unavailable

로 처리한다.


분석 가능할 경우:

- 제목/썸네일 약속을 바로 이어받는가
- 질문부터 시작하는가
- 결과를 먼저 보여주는가
- 실제 사례를 먼저 보여주는가
- 문제 상황을 보여주는가
- 자기소개가 길게 들어가는가
- 몇 초 안에 본론에 들어가는가


==================================================
8. Click Driver Taxonomy
==================================================

각 영상의 클릭 이유를 고정 taxonomy로 분류한다.

최소 다음 click driver를 사용한다.

1. problem_recognition
   "내가 겪는 문제다"

2. curiosity_gap
   "왜 그런지 궁금하다"

3. result_promise
   "이걸 보면 해결된다"

4. one_solution
   "이것 하나면 된다"

5. beginner_identity
   "왕초보인 나를 위한 영상이다"

6. loss_avoidance
   "잘못 공부하면 시간 낭비한다"

7. speed_convenience
   "빠르게/쉽게 해결"

8. specificity
   구체적인 단어/문장/상황

9. surprise
   상식과 다른 결과

10. social_proof
    조회수/성공 사례/권위/실제 사례

11. fear_or_failure
    못 알아듣음/틀림/실패 회피

12. transformation
    전에는 못함 → 이제 가능


각 영상에:

primary_click_driver
secondary_click_driver

를 최대 2개 지정한다.

자유서술 click driver를 최종 집계에 사용하지 않는다.


==================================================
9. Topic별 반복 클릭 패턴
==================================================

각 Topic에 연결된 대표 Outlier 영상들을 비교해서
"한 영상만의 특징"과
"여러 영상에서 반복된 특징"을 분리한다.

예:

Topic:
아는 단어인데 원어민이 말하면 안 들린다

대표 영상 5개 중:

4/5:
problem_recognition

4/5:
curiosity_gap

3/5:
specific native example

3/5:
"실제 원어민" 표현

이라면

이 Topic의 반복 클릭 패턴으로 기록한다.


==================================================
10. 클릭 이유의 강도
==================================================

각 Topic마다 Click Evidence Score를 0~100으로 계산한다.

Gemini가 숫자를 직접 결정하지 않는다.

결정론적 코드로 계산한다.


권장 요소:

A. 반복 Click Driver 강도 30%
B. 대표 Outlier 수 20%
C. Evidence Quality 20%
D. Title/Thumbnail 역할 분담 명확성 15%
E. Viewer Problem 일치도 15%


단:

thumbnail/hook 데이터가 없는 경우
없는 항목을 0점으로 처리하지 말고
available evidence 기준으로 weight를 재정규화한다.


==================================================
11. 주제 점수와 클릭 점수를 분리
==================================================

05의 Topic Candidate Score와
06의 Click Evidence Score를 섞어 하나로 만들지 않는다.

각각 별도로 유지한다.

예:

Topic Candidate Score: 78.9
Click Evidence Score: 91

이렇게 보여준다.


필요하면 참고용으로:

Combined Decision Signal

을 만들 수 있지만
최종 제작 결정 점수로 사용하지 않는다.


==================================================
12. 우리 채널 적용 가능성
==================================================

각 Topic에 대해:

"경쟁 영상의 클릭 구조를 베끼지 않고
우리 채널에 적용할 수 있는 부분"

을 추출한다.


예:

경쟁 영상 반복:

"이것 하나면 영어 읽기 끝"

우리 채널 적용:

"하나면 끝" 문구를 복제하지 말고

초보자가 느끼는
"왜 철자대로 읽히지 않는가?"
문제를 먼저 제시하고
구체적인 영어 단어로 호기심을 만든다.


구조를 가져오고
문장을 복사하지 않는다.


==================================================
13. 채널 정체성과 충돌 검사
==================================================

클릭이 잘 된다고 해서
우리 채널과 맞지 않는 자극적 패턴을 무조건 채택하지 않는다.

다음 항목을 표시한다.

channel_brand_fit:

- high
- medium
- low


예:

"99%가 모르는 충격적인 영어 비밀"

같은 표현이 클릭에는 유리해도
채널 철학과 맞지 않으면
brand_fit = low 또는 medium으로 처리할 수 있다.


현재 채널 방향:

- 왕초보 눈높이
- 이해 중심
- 영어 읽기/소리 원리
- 과도한 암기보다 원리
- 과장보다 납득 가능한 설명

기존 config의 channel 정보를 source of truth로 사용한다.


==================================================
14. Shorts와 Long-form 클릭 구조 구분
==================================================

Shorts와 Long-form은 클릭 구조가 다를 수 있으므로
가능하면 분리한다.

Long-form:
- 제목
- 썸네일
- 문제 인식
- 결과 약속

Shorts:
- 첫 화면
- 첫 문장
- 즉시 사례
- 놀라운 변화

같은 방식으로 분석한다.


Shorts Outlier가 Long-form 전략을
과도하게 끌고 가지 않게 한다.

16. 07 단계로 넘길 후보
==================================================

최종적으로 3~5개 Topic을

07_제목_썸네일_전략

단계로 넘긴다.


선정 기준:

- 시장 반응
- Click Evidence
- Channel Brand Fit
- Evidence Quality
- Long-form 제작 가능성
- Shorts 확장 가능성


중요:

점수 1위라고 자동 선정하지 않는다.

선정 이유를 명확하게 적는다.

17. 이번 단계에서 하지 않을 것
==================================================

이번 단계에서는 다음을 확정하지 않는다.

20. API / 비용 원칙
==================================================

이번 단계에서 기존 DB로 분석 가능하면
YouTube API를 새로 호출하지 않는다.

thumbnail_url은 이미 저장된 값을 우선 사용한다.

새 외부 API/유료 API를 임의로 추가하지 않는다.

추가 데이터가 반드시 필요하면
그 이유와 예상 quota/비용을 먼저 결과에 표시하고
자동 대량 실행하지 않는다.
