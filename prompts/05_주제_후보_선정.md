# 05. YouTube 주제 후보 선정

현재 프로젝트의 Weekly YouTube Market Research 결과를 이용하여
"다음 영상을 바로 결정"하지 말고,
시장 근거가 있는 여러 콘텐츠 주제 후보를 만들어 비교할 수 있게 해줘.

==================================================
목적
==================================================

전체 YouTube 운영 흐름:

시청자 조사
→ 주제 후보 여러 개
→ 클릭 이유 확인
→ 제목/썸네일 먼저
→ 영상 제작
→ 업로드 데이터 분석
→ 다음 주제 결정

현재:

시청자 조사 = 완료
주제 후보 여러 개 = 이번 단계

이번 단계에서는 최종 영상 제목이나 썸네일을 확정하지 않는다.

목표는:

"시장에서 실제 반응이 확인된 시청자 고민을 기반으로
내 채널에서 다뤄볼 가치가 있는 주제 후보를 여러 개 확보하는 것"

이다.


==================================================
0. 중요한 원칙
==================================================

이번 단계에서 AI가 임의로 주제를 만들어내는 것을 최소화한다.

주제 후보는 반드시 다음 근거를 추적할 수 있어야 한다.

Viewer Problem
→ Matched Search Query
→ 실제 Outlier 영상
→ Outlier 강도
→ 반복 빈도
→ 시장 수요
→ 내 채널 적합도
→ 주제 후보

즉:

"AI가 좋아 보인다고 생각한 주제"

가 아니라

"실제 시장 데이터에서 출발한 주제"

여야 한다.


==================================================
1. 입력 데이터
==================================================

가장 최근 Weekly Report와 현재 DB 데이터를 사용한다.

특히 다음 데이터를 활용한다.

- video_keyword_matches
- videos
- channel_baselines
- video_analysis
- topic_opportunities
- keyword_pool
- 내 채널 분석 데이터
- title archetype 분석 결과

Weekly Report에 이미 계산된 값이 있다면
가능하면 기존 계산 결과를 재사용한다.

YouTube API를 다시 호출할 필요가 없다면 호출하지 않는다.


==================================================
2. 대상 카테고리
==================================================

현재 6개 카테고리:

- reading
- listening
- vocabulary
- speaking
- pronunciation
- beginner

모두 분석한다.

단, 단순히 각 카테고리에서 같은 개수의 주제를 뽑지 않는다.

시장 근거와 내 채널 적합도가 강한 카테고리에
더 많은 후보가 배정될 수 있어야 한다.


==================================================
3. Viewer Problem 후보 풀 생성
==================================================

모든 Viewer Problem에 대해 다음을 집계한다.

- problem_id
- problem_label
- category
- unique matched video count
- candidate video count
- outlier video count
- 대표 Outlier 영상
- 대표 Outlier 배수
- 평균 또는 중앙 Outlier 강도
- 대표 Opportunity Score
- 연결된 search query 수
- 연결된 search query 목록
- market evidence status
- confidence
- category market demand
- my channel fit score

중요:

같은 video가 같은 problem에 여러 query로 잡혀도
video count는 1회만 계산한다.

unique video × problem 기준을 유지한다.


==================================================
4. 데이터 오염 방지
==================================================

검색어에 우연히 걸렸지만
Viewer Problem과 실제 영상 주제가 크게 다른 영상이
후보 점수를 과도하게 끌어올릴 가능성을 확인한다.

예:

영어 강세 검색 결과에
연예인/예능/밈 Shorts가 걸렸지만
실제 교육 콘텐츠와 직접 관련이 약한 경우.

이런 영상은 삭제하지 말고
후보 근거에서 다음과 같이 구분할 수 있게 한다.

- direct educational evidence
- adjacent evidence
- weak/contextual evidence

기존 Outlier 계산식 자체는 변경하지 않는다.

이번 단계의 "주제 후보 선정"에서만
evidence quality를 참고한다.


==================================================
5. 주제 후보 생성
==================================================

Viewer Problem 하나를 그대로 영상 제목으로 복사하지 않는다.

Viewer Problem을 기반으로
"한 편의 영상에서 답할 수 있는 구체적인 질문/주제"
형태로 변환한다.

예:

Viewer Problem:
영어 왕초보 어디서부터 시작해야 하나

가능한 Topic:

- 영어 왕초보는 읽기와 회화 중 무엇부터 시작해야 할까?
- 알파벳 다음에는 무엇을 공부해야 할까?
- 성인 왕초보가 영어를 다시 시작하는 순서는?
- 단어 암기보다 영어 소리를 먼저 배워야 할까?


Viewer Problem:
아는 단어인데 원어민이 말하면 안 들린다

가능한 Topic:

- 아는 영어 단어가 원어민 입에서는 왜 안 들릴까?
- 원어민 영어가 빠르게 들리는 진짜 이유는?
- 영어 단어가 문장 안에서 소리가 달라지는 이유는?
- 강세와 약화가 영어 듣기에 어떤 영향을 줄까?


==================================================
6. Topic Granularity 검사
==================================================

주제가 너무 넓거나 너무 좁지 않은지 검사한다.

너무 넓음:

"영어 잘하는 법"
"영어 공부법"
"영어 듣기"

→ 제외 또는 세분화


적절함:

"아는 단어인데 원어민이 말하면 왜 안 들릴까?"
"영어 강세 위치를 처음 보는 단어에서 어떻게 찾을까?"
"영어 묵음은 왜 생길까?"


너무 좁음:

시장 evidence가 거의 없는 단일 단어 설명

→ 별도 Shorts 후보로 분류 가능


==================================================
7. 중복 Topic 병합
==================================================

표현만 다르고 실질적으로 같은 주제는 묶는다.

예:

- 원어민 영어가 왜 빠른가
- 원어민 말이 왜 빨리 들리는가
- 원어민 영어 속도를 못 따라가는 이유

이 세 개가 같은 시청자 문제를 해결한다면
하나의 Topic Cluster로 묶는다.

하지만:

- 원어민이 빨리 말하는 이유
- did you → 디쥬
- schwa 약화

처럼 상위 문제와 구체적인 원리가 다르면
서로 다른 후보로 유지할 수 있다.


==================================================
8. Long-form / Shorts 구분
==================================================

각 주제 후보에 다음을 표시한다.

Recommended format:

- Long-form
- Shorts
- Both

Long-form에 적합:

여러 원리/예시/단계가 필요한 문제

Shorts에 적합:

하나의 놀라운 사례나 원리로 설명 가능한 문제

Both:

Long-form의 핵심 질문을
구체적인 사례로 Shorts화할 수 있는 문제


==================================================
9. 채널 적합성 검사
==================================================

내 채널이 실제로 답할 수 있는 주제인지 확인한다.

현재 채널의 핵심 방향을 기존 프로젝트 데이터에서 가져온다.

특히 다음과 연결되는 주제에 높은 적합성을 줄 수 있다.

- 영어 읽기 원리
- 철자와 소리 관계
- 발음 원리
- 강세
- 약화
- Schwa
- 연음
- 묵음
- 단어 → 문장 읽기
- 읽기 → 듣기 연결
- 왕초보가 이해할 수 있는 설명

하지만 위 항목을 하드코딩하여
시장 데이터보다 우선하지 않는다.

시장 근거와 채널 적합성을 별도로 보여준다.


==================================================
10. Topic Candidate Score
==================================================

각 주제 후보에 0~100 점수를 계산한다.

가능하면 결정론적 코드로 계산한다.

Gemini가 숫자를 직접 결정하지 않는다.

점수 요소 예:

A. Viewer Problem 반복성
B. Outlier 강도
C. Outlier 영상 수
D. Market Demand
E. My Channel Fit
F. Evidence Quality
G. 구체성
H. Long-form/Shorts 확장 가능성

각 요소의 가중치를 명시한다.

중요:

조회수 하나가 매우 큰 영상 하나 때문에
전체 점수가 폭발하지 않도록 한다.

Outlier 배수는 cap 또는 log scaling 등
안정적인 정규화 방식을 사용한다.

기존 content_opportunity_score는 변경하지 않는다.

Topic Candidate Score는
이번 단계에서만 사용하는 별도 점수다.


==================================================
11. 최소 후보 수
==================================================

최종적으로 최소 15개,
가능하면 20개 정도의 Topic Candidate를 만든다.

단:

근거가 부족한 후보를 숫자를 채우기 위해 만들지 않는다.

충분한 근거가 없다면
15개 미만이어도 정직하게 보고한다.


==================================================
12. 최종 TOP 후보
==================================================

Topic Candidate Score를 기준으로 정렬하되
단순 점수 순위만 보여주지 않는다.

각 후보마다 반드시 다음을 출력한다.

Topic:
Viewer Problem:
Category:
Recommended format:

시장 근거:
- matched videos
- outlier videos
- 대표 Outlier
- 대표 Outlier 배수
- 관련 search queries

시장 점수:
채널 적합도:
Evidence Quality:
Topic Candidate Score:

왜 후보인가:
한두 문장으로 설명


==================================================
13. 후보 다양성
==================================================

TOP20이 비슷한 주제로 도배되지 않게 한다.

예:

1~10위가 전부
"왕초보 어디서 시작?"
변형이면 의미가 없다.

같은 Topic Cluster에서 지나치게 많은 후보가 나오면
대표 후보를 남기고 나머지는 하위 후보로 묶는다.

다만 데이터상 특정 문제가 압도적으로 강하다는 사실 자체는
숨기지 않는다.


==================================================
14. 현재 Weekly Report 결과와 비교
==================================================

현재 Weekly Report의

"다음 콘텐츠 후보 TOP5"

와 새 Topic Candidate 결과를 비교한다.

다음 질문에 답한다.

- 기존 TOP5가 여전히 상위 후보인가?
- 더 구체적인 주제로 분해할 필요가 있는가?
- 시장수요는 높지만 채널과 거리가 먼 후보는 무엇인가?
- 시장수요와 채널 적합도가 동시에 높은 후보는 무엇인가?
- Outlier는 강하지만 evidence quality가 낮은 후보는 무엇인가?


==================================================
15. 이번 단계에서는 하지 않을 것
==================================================

중요:

이번 단계에서는 아래 작업을 하지 않는다.

- 최종 주제 1개 확정
- 최종 제목 확정
- 최종 썸네일 문구 확정
- 대본 작성
- 영상 제작
- 새로운 YouTube API 대량 조사

추천 제목이 필요하더라도
Topic 이해를 돕는 임시 예시 수준만 허용한다.

왜냐하면 다음 단계가:

"클릭 이유 확인"

이기 때문이다.

주제를 먼저 확보한 뒤
해당 주제의 Outlier 영상들이 왜 클릭됐는지를
별도로 분석한다.


==================================================
16. 출력 리포트
==================================================

새 리포트를 생성한다.

권장 파일:

## 12. 다음 단계로 넘길 후보


==================================================
17. 다음 단계로 넘길 후보
==================================================

TOP20 전체를 다음 단계에서 모두 깊게 조사하면 비효율적이다.

따라서 마지막에

"클릭 이유 분석 대상으로 넘길 후보"

5~10개를 별도로 선정한다.

선정 이유를 각각 표시한다.

예:

- 시장 반응 강함
- 채널 적합도 높음
- 반복 Viewer Problem
- 여러 Outlier에서 검증
- Long-form + Shorts 확장 가능


하지만 이것은 최종 제작 결정이 아니다.

다음 단계:

06_클릭_이유_분석

의 조사 대상일 뿐이다.


==================================================
18. CLI
==================================================

가능하면 기존 CLI 구조를 유지하면서
다음과 같은 명령을 추가한다.

python -m research.cli topics

필요하면:

python -m research.cli topics --top 20

기존 CLI 명령은 깨뜨리지 않는다.


==================================================
19. 테스트
==================================================

최소 다음을 테스트한다.

1. unique video × problem 집계
2. 같은 problem의 query 중복으로 영상 수가 부풀지 않음
3. Topic 중복 병합
4. evidence quality 분류
5. insufficient_data 처리
6. Topic Candidate Score 결정론적 계산
7. 극단적인 Outlier 하나가 점수를 지배하지 않음
8. channel fit 반영
9. Long-form/Shorts/Both 분류
10. 최소 evidence 기준
11. TOP20 정렬
12. Topic diversity 처리
13. Weekly Report TOP5와 비교
14. 리포트 생성
15. 기존 전체 테스트 회귀 없음

전체 pytest를 실행한다.


==================================================
20. 실제 데이터 검증
==================================================

현재 DB에 이미 수집된 데이터를 이용해 실제 실행한다.

가능하면 새로운 YouTube API 호출 없이 수행한다.

실행 후:

reports/topic_candidates_2026-08-17.md

를 실제 생성하고 확인한다.

특히 현재 데이터에서 다음 신호들이
후보에 제대로 반영되는지 확인한다.

- reading 시장수요 강함
- listening 시장수요 강함
- pronunciation과 내 채널 교집합 존재
- 영어 왕초보 시작점 반복
- 묵음
- 강세
- 연음
- 원어민 듣기
- 단어 → 문장 읽기

단,
이 항목들을 강제로 TOP에 넣지는 않는다.
실제 점수 결과를 따른다.
